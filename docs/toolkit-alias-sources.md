# 检索别名的逐行来源

2026-11-07，接续 `f219ff6` 的 P2 实施。背景整理合并到本地检索的别名现在保留来源快照；来源撤回、过期、修订或索引清空后，受影响行不再扩展新查询。编辑器保留原文供核对。

## 行为

- 每个新增别名行绑定引入它的背景依赖。只去除行首尾空白来识别同一行；原样保存、重排、空白变化或新增其他行都不解除旧行保护。
- 已存在的手填行不会被模型接管。新背景重复建议旧行也不会重新绑定其来源；恢复原来源会恢复有效性，实际改写或显式“转为手动别名”则成为用户维护的配置。
- 新编辑器保存比较读取时的完整旧值，来源合并已改变文本时拒绝覆盖并保留草稿。保存 API Key 与别名编辑分离。旧调用方传入 aliases 仍支持，但同样经过逐行来源处理；新界面使用有旧值检查的独立接口。
- 来源失效只影响相关行。没有来源记录的旧版别名继续兼容，不推测历史归属；这不表示已确认其正确性。
- 元数据沿用现有 SQLite settings，每批快照共享一次，无新数据库、向量服务或模型调用。移除别名时裁剪不再引用的派生元数据，不删除原文件。元数据上限 8 MiB，超限时整个合并事务回滚，可精简旧别名或不合并术语。
- 手动核对和保存接口仅主窗口可用，采集或会话期间不能修改；展示窗口不新增模型、资料配置权限。文字回答、截图回答与手动本地检索均读取当前有效别名。

## 验证

核心完整回归 97 项通过；原生 interview 回归 52 项通过，1 项真实废纸篓测试忽略。前端 28 份脚本通过，包含实际别名组件、整页控制与既有流式/取消/恢复契约；TypeScript 检查通过。

8 个新核心案例覆盖：多批来源独立失效、手填重复行保留、重排/空白/普通保存、显式核对原子性、过期编辑快照、重复合并、版本修订/过期、索引清空、无效元数据、8 MiB 边界及事务回滚。真实 FTS 合成案例验证：撤回别名来源后，别名不再把查询扩展到另一份仍有效文档；该文档仍可由自己的原词检索。

原生 IPC 合成测试覆盖主/展示窗口、会话锁、生命周期锁、旧值冲突和 Key 保存不覆盖别名。Chrome 中使用真实组件与应用样式、内存 IPC，验证原样保存保持待核对、逐行接管不影响另一行，布局检查截图留在本机交接目录。这些不代表安装版或真实通话验收。
