# 多来源更新与改名保护

2026-11-08，接续 `6549357`。本轮处理背景资料的稳定身份和用户核对状态；不会修改实时提示、启动模型或切换安装版。

## 问题与修正

以前排除记录只匹配当前路径。同一背景来源ID改名后，旧排除记录不能命中新路径；原路径上的有效期也没有带过去。新组合测试先复现了这两个问题。

背景来源以 `.背景/<64位来源ID>/` 作为稳定身份，普通本地资料仍按资料根目录和路径区分。排除查询兼容旧路径记录；显式解除排除时更新该ID下的旧记录，并与版本更新在同一事务中提交。不同ID的同文副本不会被一并排除，也不能因此变成已确认个人事实。过时路径或哈希的操作继续拒绝。

改名导入携带上一当前版本的核对日期、核对哈希和状态。提取内容/名称改变后仍需重新核对；改回旧名字不能恢复旧名字下的过时确认。旧版本遗留的孤立核对记录只用于保留日期限制，不能证明新版本已经确认。未删除原文、历史修订或旧准备候选。

新增 `background_exclusion_identity` 派生索引，同一条规范化表达式同时用于写入索引和读取。旧库打开时只补建索引，权限记录和资料版本不变。不新增产品数据库、模型接口或网络调用。

## 组合覆盖

`crates/interview-core/tests/background_update_matrix.rs`：

| 场景 | 直接断言 |
|---|---|
| A/B资料分别应用岗位和背景，撤回A后改名 | 检索、外发背景输入、准备导出均排除A；B和其设置/别名仍有效；原始本人发言保留 |
| 有效期核对 → 改名 → 新核对 → 改回原名 | 保留当前核对日期，旧确认不复活；注入提交失败时资料、版本和旧日期一起回滚 |
| 旧路径排除记录 + 两个同文独立来源 | 同ID改名仍排除；其他ID独立；解除失败完整回滚，明确解除后可检索 |
| 旧版丢失当前名称的核对记录 | 历史日期保留但不代为确认，必须重新核对 |
| 无派生索引的旧库重开 | 原权限内容和资料版本逐项不变，查询计划实际使用新索引 |
| 多来源候选 → 本人修订 → 撤回另一来源并改名 → 再保存 | 旧候选可查可导出但不可恢复，当前候选只含有效来源；重开库后三版历史和人工修订仍在，事实卡未被确认 |

原生撤回回归同时扩展到三路回答：所有在途取消令牌都收到取消，旧任务尚未退出前保持占用与生命周期屏障，不提前确认撤回，也不停止现有会话。

## 验证结果

最终本地143项核心检查、61项原生检查通过；原生1项真实废纸篓用例按原约定忽略。新增六项组合用例均通过；十项冻结题库/口语输入及原提示边界未改。测试只使用合成临时库与本机loopback；不等于安装版、真实模型或实际音频验收。

## 开销

首次直接兼容旧路径的实现出现额外扫描开销，未作为最终版本。最终使用派生索引；复现 `cargo run --locked -p interview-core --example measure_source_exclusions`。

Rust debug/sqlx、暖SQLite、2,000份合成资料、每组1次预热+15次计时，同一正确查询先不建索引再建索引：

| 排除条数 | 无索引 p95 | 有索引 p95 |
|---|---:|---:|
| 0 | 4.87 ms | 6.53 ms |
| 1 | 10.74 ms | 6.98 ms |
| 10 | 68.96 ms | 7.10 ms |
| 100 | 563.49 ms | 7.03 ms |
| 100，来源已改名 | 561.43 ms | 6.61 ms |

这是完整权限谓词扫描的局部测量，不含FTS、IPC、ASR、模型、导入和进程启动。零排除时有约1.66 ms的该次p95差异；不能据此承诺真实首字、总费用或整场资源下降。未新增模型输入字段或API调用。

## 尚未代替的验收

这六项组合和原生三路取消不代表完整PRD、所有源更新顺序或真实模型保真已经通过。背景worker部分失败/续作、真实宿主四角色推理、口语质量/实际费用、安装版文件操作和长会议仍按各自清单推进。C5消费与安装切换边界不变；实时legacy、按需规则、Harness²和AI2默认关闭保持。
