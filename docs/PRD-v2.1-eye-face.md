# 听弦 PRD v2.1 本地眼部校正与脸部替换

日期：2026-11-06。本文是 PRD v2.0 的功能修订，面向产品、Windows 开发与验收人员。开发顺序为：保全并冻结旧数字人路线，回到数字人开发前的 Windows 源码基线，优先交付本地眼部校正；脸部替换只保留界面和适配契约。文档版本不等于安装包版本。

**2026-11-07 范围修订 AV-SYNC-20261107：** 听弦接收原始摄像头画面和本人麦克风原声，校正眼神后，经统一时间轴与有界缓冲，把同步后的画面和本人原声分别交给虚拟摄像头、虚拟麦克风，再由会议软件使用。虚拟麦克风与原声同步现为 R10E 完整交付的必需环节；不再以会议软件直接使用物理麦克风作为同步方案。此变更不解冻 TTS、换脸、口型生成、完整数字人或代理，也不授权当前开启真实采集。现状、技术差距和分层验收见[同步原声契约](eye-av-sync-scope-2026-11-07.md)。

用户已确定上述方向；本文新增的性能数值属于拟定验收目标，尚不是实测成绩。R01—R09 的基础能力及未完成验收继续有效。本文与旧 PRD 冲突时，以本文关于摄像头增强、数字人和优先级的条款为准；不删减其他需求。

## 1 目标与范围

### 1.1 眼部校正优先

使用真实摄像头画面，在本机识别人脸、头姿和眼区，修正视线后融合回原画面。保留真实口型、声音、表情、身体和背景，让用户看屏幕时仍有较自然的视线表现。

该模式仍展示本人真实面貌。它不提供身份隐藏，也不生成完整替身。没有摄像头时不能使用，不自动切换成照片数字人。

### 1.2 脸部替换后置

预留两个后续模式：本人原声驱动脸部，以及用户确认文本后由 TTS 生成语音并驱动脸部。局部嘴部重绘、整脸驱动、3D 形象及云渲染属于后续适配器候选，不同时立项实现。

首阶段仅交付设置页中的未启用入口、能力查询、接口文档和不可用状态。不得以该入口为由安装模型、调用服务、启动渲染器或延续旧数字人功能开发。

### 1.3 冻结旧路线

冻结 LivePortrait、3D 预览、照片注册、原声口型和完整数字人相关开发。已有源码、未提交文件、测试、许可证、运行时和研究证据保留；通过独立分支与本地恢复资料保存，后续按需审查复用。

R11 全程自动代理同时冻结。语音合成与脸部接口的存在，不构成自动替用户回答的授权或完成证据。适用范围继续为模拟面试、练习，以及参与者明确允许合成形象或代理的交流。

## 4 R10E 本地眼部校正

### 4.1 用户流程

在主控制窗打开“视频”设置，选择摄像头、查看本地预览并启用“视线校正”；需要同步会议输出时，明确选择本人麦克风并授权原声采集，再显式开启音视频输出。用户在会议软件中手动选择“听弦虚拟摄像头”和“听弦虚拟麦克风”，分别核对画面与本人声音。仅视频预览或输出可独立使用，但不得标为完整音画同步。

首次启用分别完成实际摄像头和麦克风访问授权。本地预览不等于已向会议输出。窗口恢复、重启、读取会话或切换工作区均不得自动开启摄像头、麦克风或任何输出。

视线校正、本人原声输出、ASR、AI 请求拥有独立授权与状态。开启视频预览不能隐式采集音频、启动转写或请求模型；同步会议输出须同时确认两路媒体条件。

### 4.2 画面要求

- 首轮支持单人、单路摄像头、720p、30 fps 输入；1080p、多摄像头与多人修正后置。
- 只修改眼区及必要的融合边缘。脸部其他区域、嘴部、身体和背景使用原始画面；在编码前固定色彩格式下验证处理区域外无非预期重绘。
- 保留真实眨眼、眼睛闭合、眼睑形状及可辨识的眼部特征。不能为了维持注视而强行睁眼。
- 默认适度朝向摄像头，并允许轻微自然视线变化；不以持续锁死瞳孔为目标。
- 头部或视线超出有效范围时平滑减弱校正。遮挡、反光、低置信度、快速运动和跟踪丢失不得持续生成错位眼睛。
- 参数以实际供应商能力为准。只有适配器提供并验证过的强度、范围或自然移视能力才显示控件，不把自定义后处理伪装成原生 SDK 参数。
- 不承诺任意姿态无痕，不把眼部校正描述为隐藏真实身份或绕过身份核验。

### 4.3 本地处理与运行时

推理在本机完成；摄像头帧、眼区、关键点和人脸特征不发送到外部服务。下载可选组件是独立操作，不携带摄像头数据，不在启动应用时自动下载。视频模式默认不录制；诊断默认仅记录计时、状态和资源数值。

优先集成 NVIDIA Maxine AR SDK Eye Contact，采用独立可选运行时。NVIDIA Broadcast 可作为现成效果参照或用户自行选择的外部摄像头来源，不将 Broadcast 当作可直接重新分发的产品 SDK。Windows Studio Effects 作为具备兼容 NPU/驱动的设备后续适配，不作为所有 Windows 电脑的默认能力。

2026-11-07 按用户补充要求，先验证官方公开 AR SDK 0.8.7 Ada 与匹配示例；新版 NGC Core 的访问资格不是此路线的前置条件。两条路线分别固定 ABI、组件与实际许可，详见[旧版获取与许可记录](eye-ar087-acquisition.md)。本机开发测试授权、商业使用和第三方二进制再分发分别判断；不因后两项尚未明确而把已允许的本地验证一并阻塞，也不因本地验证而推定生产交付获准。

固定 SDK、模型、GPU 支持范围、驱动、校验摘要与许可版本。基础安装包继续支持无独显的转写和资料功能；不把眼部模型、CUDA Toolkit 或 Visual Studio 变成普通安装用户的强制依赖。运行时只在用户启用能力时加载，停止后释放相应资源。组件下载与测试默认使用 D 盘。

缺少 GPU、驱动不兼容、模型损坏、许可或组件不可用时，禁用眼部校正并提供具体原因。不能静默改为云处理、降低其他基础功能可靠性，或假装使用了 CPU 等价实现。

### 4.4 虚拟摄像头与故障行为

虚拟摄像头属于眼部方案首个完整交付范围；只在应用预览窗口中出图不能算交付。复用成熟输出机制或采用受支持的 Windows 实现；需要独立组件安装或系统授权时准确说明，不承诺所有驱动均无需管理员操作。

视频状态分别记录：关闭、准备中、本地预览、向虚拟设备输出、暂停、故障。会议是否选中该设备、对端是否看到画面，不能由“已写入虚拟设备”推断。

默认故障输出中性占位画面并停止处理；不得自动切换成原摄像头或恢复历史帧。用户可预先明确选择“校正失败时继续原画面”，界面须显示当下已停止校正。脸部替换模式未来不得继承这种原画面回退授权。

用户点击“关闭视频”或紧急停止后，立即停止提交新摄像头帧，已有虚拟输出切换中性画面，并释放采集；进程异常也需要由输出端看门狗避免无限停留在最后一帧。摄像头被占用、拔插或权限撤销时提供恢复入口，不自动争抢其他摄像头。

同步会议模式中，任一路权限、时钟或设备失效默认使两路进入安全状态：中性画面与静音，清除待输出缓存并递增同步代次。紧急停止同时撤销视频和原声输出；不得自动改用物理麦克风、原始画面或其他设备。单独关闭原声不强迫关闭本地视频预览，但完整同步状态立即结束；重新输出需要明确操作。

### 4.5 本人原声与音画同步

听弦获取用户明确选择的本人麦克风原始音频流。只作必要的格式转换、时钟漂移补偿和有界延迟，不生成、替换或克隆声音，不等待 ASR 或 AI 结果。原始嘴部、面部身份和身体动作保留；眼部校正后的视频与同一采集时段的原声共同调度。

音视频使用经核验的共同单调时间基准，保存实际采集时间、设备样本位置、时钟映射和不连续标记，不以处理完成顺序代替采集顺序。依据眼部处理耗时与设备位置安排有界播放时间，持续估计、补偿输入/输出时钟漂移；固定延迟或单次校时不能证明长期同步。视频过期时丢帧并记账，不通过无限增加音频延迟追赶。

默认只将本人原声送入虚拟麦克风。系统 loopback、对端声音、听弦输出回采、AI 草稿和参考答案均不得进入这条输出路径；数字路由隔离不等于已消除扬声器到麦克风的声学回声，耳机/实际会议另测。ASR 可在单独授权后并行消费本人流，但不阻塞、控制或替代对外原声。停止 ASR 不得误停明确开启的媒体输出；停止媒体输出也不擅自丢弃其他已授权会话。

会议软件直接选物理麦克风属于独立路径，听弦不能控制它的同步、静音或延迟，不显示“已同步”。完整验收须在接收端核对两种听弦虚拟设备，音画偏移绝对值目标 P95 ≤100 ms，并报告总延迟、样本数、失败、漂移、丢帧/音频欠载及测量误差。无音频测试授权时只做合成/无声检查；需求修订不等于实际同步输出已实现或通过。

## 5 R10F 脸部替换保留范围

脸部替换属于独立能力，不依赖眼部模型能否生成完整脸部。未来目标是让本人原声或已确认文本对应的合成语音驱动口型、下颌、脸颊与表情，必要时融合到真实视频或使用授权形象输出。

| 预留模式 | 音频来源 | 本轮状态 |
| --- | --- | --- |
| 本人原声 | 用户实际麦克风，必要时同时间线缓冲 | 仅接口和页面，未实现 |
| 确认后发声 | 用户确认文本经流式 TTS 生成音频 | 仅接口和页面，未实现 |
| 自动代理 | 模型自行组织并输出回答 | 冻结，不在新首期范围 |

本轮只保留供应商能力说明、配置 schema、输入/输出与取消契约，以及“脸部替换 · 暂未开放”的不可启动界面。不接入 MuseTalk、Audio2Face、Tavus 或 LiveAvatar 的运行时，不导入个人素材，不配置真实 Key，不发起付费请求。

未来启用时必须使用同一份音频与统一时间戳驱动口型并播放，缓冲有上限，打断同时取消声音和后续画面。真实本人发言、AI 草稿、TTS 已输出片段分别记账；合成声音不能记录为本人自然说过的话，也不能回流触发新的对方问题。

听弦只记录可观察的“生成”“提交到设备”等状态；对端收到需要独立验证。形象、声音、低延迟和自然度不由供应商宣传或模型 infer FPS 代替。

## 6 界面与交互

沿用听弦名称与既有图标。保持白底、石墨黑 `#17181A`、少量金属银 `#C5C7CA`、强调色 `#00E5EF`，合体布局约 20% 操作与 80% 对话，拆窗入口继续显眼。

“视频”是主控制窗中的独立设置面板，默认关闭。常用控件包括摄像头、本人麦克风、预览、视线校正、原声静音、音视频输出和停止；缺少输出能力时显示具体原因，不以可点击开关冒充实现。模型版本、自然移视、工作范围与同步诊断放入高级设置。只保留能帮助操作的状态说明，遵守 “Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.”

脸部替换在同一面板中保留低优先级入口，进入后可看说明与未启用状态；启动控件不可用，不显示虚假的模型就绪或生成进度。不开设第二个常驻数字人工作台，不抢占回答阅读区。

拆分展示窗继续只读，不采集摄像头、不运行模型、不持有 Key、不安装组件。它只能接收必要状态；不因显示窗重开产生第二条视频流。字号、窄窗、阅读锁定与返回最新答复的规则不变。

## 7 适配边界与数据契约

复用现有 Tauri、Rust 和 React 架构。主控制端统一管理生命周期；GPU 处理尽量在独立工作进程中运行，失败不能带崩 ASR、问答和资料功能。此处规定最小契约，不要求先建立通用媒体框架。

| 契约 | 最小内容 |
| --- | --- |
| `VideoEffectCapabilities` | provider/version、supported、原因、输入格式、分辨率/帧率范围、本地或云端、所需组件及许可标识 |
| `VideoFrame` | stream_id、generation、frame_id、capture_pts、clock_id、映射版本、尺寸/色彩格式、本地帧句柄；采集时间与输出 PTS 分开 |
| `EyeCorrectionProvider` | 查询能力、准备、处理帧、更新已支持参数、停止、释放；输出处理状态和计时 |
| `VideoOutputSink` | 开始、按时间戳提交帧、中性画面、停止；不等同于对端接收确认 |
| `FaceReplacementProvider` | 预留能力查询、会话准备、视频/音频块提交、取消、停止；未实现时返回 `not_implemented` |
| `AudioChunk` | audio_source=self_microphone、精确设备 ID、序号、sample_rate/channels/format、样本起点/长度、capture_pts、clock_id、映射版本、generation、不连续/静音/时间戳错误标记、本地 PCM 句柄；不得接受 loopback 或虚拟输出回采 |
| `AvSyncSession` | 同步 generation、两路授权与状态、共同时间轴、时钟观测/漂移、目标延迟与硬上限、两路有界队列、停止/重启和失效策略 |
| `AudioOutputSink` | 查询真正的系统麦克风端点能力、准备、按时间线提交 PCM、静音、刷新、停止；禁止默认扬声器回退，独立设备租约/看门狗 |
| `EffectMetrics` | 采集/处理/排期/提交时间、有效/重复/丢弃帧、两路队列深度、缓冲延迟、音频欠载/不连续、漂移/重采样、错误；不含原媒体，不将本地估算标成接收端实测 |

停止、换设备、切换模式、清空与恢复会更新 generation；旧帧、旧音频、旧回调全部丢弃。眼部待处理队列上限初定为 2 帧，过期优先丢弃，不能积压追赶；准确统计丢弃，不能重复最后一帧来充有效 FPS。同步缓冲另有明确的毫秒数/字节数硬上限，音频连续消费，欠载输出静音且记账；不得照搬视频“最新块替换”来截断正常语音。清空、故障和重启须排空双方旧缓存与设备侧待播数据；做不到时禁止重启并报告。

共享帧尽量避免重复拷贝。跨进程若使用本地网络端点，仅绑定回环地址并限制访问，不开放局域网。精确 IPC 与虚拟摄像头实现由独立技术设计确定。

配置新增独立版本，不修改旧资料格式与应用数据标识。恢复只恢复偏好，不恢复采集、输出、TTS、云请求等运行副作用。

## 8 验收指标

### 8.1 眼部首期目标

以下门槛用于决定是否可进入日常会议，不是当前性能声明。测试固定输入、硬件、驱动、版本与预热条件，记录失败和丢帧，不能只剔除慢样本后报告通过。

| 项目 | 目标 | 测量边界 |
| --- | --- | --- |
| 本地处理 | 眼部校正与原声同步不向模型/第三方处理服务外发媒体；不触发 AI 请求 | 显式提交给本机会议软件及其会议传输另算授权输出；组件下载独立记录 |
| 输出帧率 | 720p/30 fps 合格输入下，10 分钟有效输出平均 ≥29 fps，至少 99% 的一秒窗口 ≥25 fps | 按唯一且实际呈现的画面统计；分别报告虚拟设备和会议接收端，不用 JS 回调计数 |
| 本机视频链路 | 帧到达本机采集回调至虚拟输出提交 P95 ≤50 ms、P99 ≤100 ms | 截止点在 GPU 完成后；包含新增同步等待，分别报告处理/等待/总计，不隐藏缓冲成本 |
| 端到端同步 | 会议接收端音画偏移绝对值 P95 ≤100 ms | 会议同时选择听弦两种虚拟设备；可对齐事件与漂移长测，报告总延迟、样本/失败数和误差 |
| 停止 | 停止后 500 ms 内不再提交新摄像头帧和本人音频块，1 秒内释放该同步会话采集 | 同时确认中性画面、静音及旧缓存不回放；已交给会议/网络的片段不能追溯撤回，接收端尾部另测 |
| 自然度 | 固定样例中无严重眼睛错位、强行睁眼、明显边缘接缝或突跳 | 对照原片和输出，记录发生时间；轻微瑕疵单列，用户审阅后决定可接受范围 |
| 连续运行 | 30 分钟无崩溃、OOM、无界队列；后续 60 分钟与基础会议并行 | 记录独显/共享显存、内存、GPU 计算/编码和帧时间，不假设所有模型可同时常驻 |
| 基础能力 | 开关视频不破坏采集状态、资料、输入草稿、三路问答及只读展示 | 运行相关回归，再核对实际安装版 |

眼部处理本身、虚拟设备、本机应用、会议接收端分层计时。跨机器不能直接相减未同步时钟；使用统一可观察标记或经过核验的时钟方法。重复、占位和冻结帧分别计数。

### 8.2 脸部接口本轮门槛

- 未实现的适配器不启动摄像头、麦克风、TTS、网络或模型下载。
- UI 清楚显示不可用原因；恢复配置和误点入口均不产生外部副作用。
- 合约允许后续单一音频时间线、打断、已输出区间和模式隔离，不提前实现复杂调度器。

脸部未来探索暂沿用 720p 有效输出 ≥25 fps、本人原声路径新增延迟 P95 ≤400 ms、音画偏移绝对值 P95 ≤100 ms 的目标；TTS 首音延迟另列。正式启动时重新评审，不把这些目标设为眼部首期依赖。

## 9 有决策价值的验证顺序

每轮先写假设、影响的决定、停止条件和证据范围。明确失败的方向不重复遍历全部设置。

| 轮次 | 假设与决策价值 | 停止条件 | 影响的结论 |
| --- | --- | --- | --- |
| E1 合成/授权离线输入与许可 | 锁定组件能在目标 Windows/GPU 上正确加载并处理授权测试视频；决定是否继续原生集成 | 许可不允许当前开发测试、关键组件无法合法取得、模型校验失败或定位后确认无法解决的兼容性障碍；不反复重跑同一失败 | 本地可行性，不能称为实机摄像头或商业分发通过 |
| E2 眼区质量 | 轻度偏视可自然修正，闭眼/遮挡/超范围可退回；决定默认范围 | 严重错位或眨眼破坏稳定复现后先修根因，不继续堆样例 | 适用角度与自然度边界 |
| E3 输出与停止 | 两路虚拟设备可被会议软件识别，共同时钟、原声同步和停止语义正确 | 原帧/未授权音频泄露、回声路由、停止无效、旧数据回放、队列超界 | 同步输出支持范围；合成、设备、会议分层 |
| E4 资源共存 | 与本地 small、问答和拆窗并行仍满足目标 | OOM、基础链路失稳或持续不达帧率 | 默认配置及并发支持范围 |
| E5 安装与会议 | 普通安装环境和真实会议能复现短测结果 | DLL 写入拒绝、资料风险、媒体条件未授权或同步失败 | 安装版和长会议验收 |

摄像头、麦克风、播放与会议测试分别按当前用户许可执行。现有“暂不采集音频”的约束继续有效。缺少条件时使用合成资料推进，并明确留下待测项；不以合成回放替代真人与接收端证据。

## 10 资料保护与发布

所有已有资料、运行时、下载和诊断保留。新开发使用独立 worktree；旧数字人分支只做冻结归档，不通过删除目录或 reset 覆盖。备份先核对真实文件路径，不能把 Codex 重定向缓存误当成桌面应用资料。

安装与应用数据互相独立。建立源码基线不卸载当前应用，不恢复旧数据库。任何后续安装都先检查当前进程、未保存输入及资料，并核对包源码与 SHA-256；不关闭防护、不添加信任绕过、不手工补系统 DLL 来冒充安装成功。

新可选组件需记录第三方许可、模型来源与摘要。只有本地运行不等于开源；SDK 示例源码、模型、运行库和素材的许可分别核对。基础包不携带脸部实验模型，不修改已有发布资产，测试版不擅自改为稳定版。

每轮账本至少记录：commit/安装包摘要、环境、输入样例、步骤、预期/实际、时延与帧率口径、日志位置、恢复结果、未测项。公开提交只包含可公开代码、文档和合成材料，不含真实脸部图像、Key、简历、录音、会话数据库和原始系统跟踪日志。
