# 云转写用量记录

2026-11-08 源码候选。补齐 R02 的观测与会话恢复，不修改 C0—C4 的记忆策略，不启动 C5 付费试验。

## 计量口径

[百炼服务端事件](https://help.aliyun.com/zh/model-studio/fun-asr-server-events)（2026-11-08 核对）定义 `usage.duration` 为当前任务计费时长；partial 的 usage 为空。每次握手有独立 UUID，恢复、双路和重试不复用同一 task。

原生 `interview_cloud_usage.rs` 记录每个连接尝试的来源、任务 ID、状态和最后收到的累计秒数。同任务 3、3、8 秒只记 8 秒，不相加为 14 秒。任务正常结束不代表拿到了最终账单；未返回的尾段、取消和失败可能另有用量。连接尝试可能在发送音频前就失败，不能将每次尝试称为已计费请求。

零与未知分开；缺失 usage 不填零、不从墙钟或音频长度推算。已观察累计值保留，递减/不合法的数值防御性标记不一致，不进入已知合计。已知秒数是观察结果，不是实际语音时长、模型 tokens、费用估算或供应商账单。小数展示最多三位；整数毫秒累加避免大数合计超出 JavaScript 安全整数。

转写被静音、旧 epoch 或取消规则过滤前，先记录该结果中已收到的 usage。它只保留统计元数据，不让旧文字回填，也不让本人发言触发回答。新的只读 IPC `interview_cloud_asr_usage` 仅主窗口可用，展示窗拒绝访问；原有 usage 事件增加 `task_id`，没有增加外部网络调用。

## 保存与恢复

两个主窗口入口共用 `use-cloud-usage.ts` 和 `interview-cloud-usage.ts`。只有显式开始云采集才建立当前 scope；每秒读取原生内存统计，恢复和打开页面不重连 ASR。客户端路由切换共享当前 scope。

新增可选快照字段 `cloud_asr_usage`，复用现有会话 SQLite、恢复草稿和导出/清理归档，没有新数据库。即使没有一条转写，也可保存非空用量记录。保存前刷新；同步失败明确阻止保存，原数据保留。恢复中的 connecting/running 标为 interrupted，不自动联网；旧快照缺字段显示旧记录用量未知，并在再次保存时保留这个事实。清空成功后新 scope 隔离旧结果，清空失败不重置本次统计。统计不进入回答提示，不改变聊天跟随位置。

原生内存每 scope 最多 2048 次连接、每进程共 20000 次；恢复快照最多 20000 条。恢复已有超过 17952 条时阻止继续云采集，为下一 scope 预留 2048 条，避免收到了统计却无法保存。满额明确提示保存后新会话或重开，不静默淘汰。清空后不可见的旧 scope 元数据仍在本进程有界缓存，退出释放，不含文字、录音或凭证。

新读取器兼容原 v1/v2 快照；不保证旧应用理解新增字段。回退前保留新快照/数据库副本，不用旧程序覆盖。运行时统计首先在 RAM；已有每秒恢复草稿负责检查点，进程崩溃前尚未写入的数据仍可能缺失，不能称为完整计费审计。
