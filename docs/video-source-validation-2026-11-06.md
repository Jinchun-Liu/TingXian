# Windows 原生媒体源无设备注册验收

实现提交：`6ba5a8072696ef5648a233f690f1aa3ab00d7e1e`，分支 `feat/windows-eye-local-20261106`。本轮新增 [原生媒体源](../video/windows/README.md)，没有修改现有前端、Rust 主程序、Python 助手或基础安装包装。UI 仍采用已发布 Mac 0.6.5 基准。

## 实现范围

独立 COM DLL 实现 Media Foundation 直播媒体源、一路 720p/30 fps NV12 视频格式和本进程内的已处理帧接收接口。每次启用产生新 generation，拒绝错误代次、非递增帧号、错误长度和失效时间戳。待处理输入只保留最新一帧，实际交出样本后分别统计唯一、重复和中性样本；输出样本分配池为四个，与输入等待队列分开。

默认输出中性画面。停止、暂停和源退出清除缓存并使旧代次失效；输出端发现已保留帧超过 250 ms 未更新后，切中性画面并禁用该代次。需要显式重新启用才恢复。代次锁持有到 MF 样本事件提交，防止停止返回后迟到回调再提交已准备的旧画面。

接口是**进程内**能力，尚未实现 GPU worker 到 FrameServer 的跨进程传输。DLL 不含物理摄像头包装、设备枚举/打开、音频、网络、GPU SDK、自动下载或注册逻辑。没有安装/注册虚拟摄像头，没有接入 Tauri 控件或会议软件。不能把这个媒体源称作完整虚拟摄像头交付。

## 验证决定

假设：实际 COM/MF 源可在无 GPU、无设备注册条件下，按约定交出合成 NV12 样本，并在停止、失效和恢复时保留中性默认。决策价值：决定输出组件能否进入受限 IPC 与独立设备安装阶段。错误/旧像素、无界缓冲、崩溃、COM 泄漏或意外媒体副作用均阻止推进；修正根因，不弱化断言。

未执行性能实验。格式声明的 30 fps、1.46 秒的 CI 测试总时长和 250 ms 的失效阈值，都不是有效帧率、GPU 处理耗时或会议停止时延成绩。

## CI 与目标机

本机为 Windows 11 `10.0.26200`，64 位进程。本机没有所需 MSVC C++ 工具，现有 Windows SDK 只有 `10.0.19041.0`，因此没有本机编译成功的声明。将同一提交的 CI artifact ZIP 下载到 D 盘，对照 GitHub 元数据核验完整提交、大小及 SHA-256，再提取并记录每个文件摘要。

## 失败恢复与未测

本轮编译、CI 和本机运行没有失败。合成检查覆盖未设置分配器时拒绝后恢复、输出池耗尽后释放恢复、失效/停止后的旧帧拒绝及新代次恢复。当前听弦进程保持原状，没有关闭应用、升级、卸载、改变用户资料或安全防护。
