# 离线跨块岗位准备整合

2026-11-07，接续46138a3的桌面回导。工具包0.6候选，安装版未更新。新增流程处理同一项目分散在多块、岗位缺口重复和职责矛盾，保持来源及原始候选可核对。

## 实现

- `consolidation-catalog/plan/input/collect`：离线Lead先提议项目分组，再按岗位要求/故事组读取完整原文。同名不自动合并，不确定可以分开；父候选从当前scope与原preparation响应重建。
- 每张原故事有明确映射；每条未保留证据有省略理由；每个原始缺口有去向。补齐经历缺口须引用保留的个人来源，参考答案不能冒充经历。未知和未完成状态不升级。冲突保留至少两条引用，不按票数或文件时间定真伪。
- 输入hash绑定实际任务、来源、分组及预算，未变块可复用；缺块、重复、越界引用、超窗口拒绝整包。v2候选保留父v1候选、全部先前选中来源和整合审计；不接受递归套候选。
- 原生端兼容v1/v2并重核父候选、当前有效资料全集、修订、原故事、缺口、预算及省略覆盖。保存仍比较资料版本和已存候选版本，不改事实、设置或实时输入。来源变化后旧视图仅保留查看。
- 桌面先展示未决冲突，原文、原故事、省略/缺口处理可展开，长内容分批显示。具体命令及契约见[可移植入口](../interview/toolkit/references/preparation.md#跨块整合工具包-06)。

四角色仍为离线Lead、HR、Mentor、Consultant，程序校验不是第五角色。最终评审须绑定整合后的同一候选；额外底层请求不藏在12个顶层回合里。实时按需加载不变，active policy=legacy，Harness²=false。工具无模型传输、不读Key、不挪用旧30元预算。

## 开销和限制

20份虚构资料专门设为一来源一块（input cap=2843）观察缓存，不是默认32768分块的生产成本。原准备20个计划请求；整合另需1次分组+2项岗位要求+20组故事，共23次，不含四角色评审/重试。输入上界分别56660与113544字节估算，整合最大单次18114；默认输入上限65536、输出预留16384、安全4096，窗口取实际声明与262144较小值。

原样可复用22个处理块及分组；改一份来源后复用19块、重做3块及分组。6次本机离线准备/整合p50约8.86ms、最近秩p95约9.40ms，进程峰值约29.9MiB；不含模型、网络、桌面或ASR。复现脚本 `scripts/measure-toolkit-consolidation.py`。实际tokens、首字/完整时延、usage、费用未知，不当零、不宣称省费。

结构/引用检查不能证明语义合并正确、岗位匹配更好或口语更自然。既有12题精简候选仍只有约14.5% UTF-8字节下降证据，25%目标未达；真实质量及费用配对未进行，候选不晋级。

整合仅处理第一阶段选材，不是整库矛盾检出。单个岗位或组超预算明确拒绝，尚无无限层级整合；需缩小任务/选材、细分分组或在实际窗口内提高上限。含父候选总包最多16MiB。准备视图多版本恢复、完整多来源更新矩阵、真实四角色A/B/C、Codex/Claude Code推理回导、安装版恢复、云ASR/视觉/长会议保留后续阶段；本轮不打包或重启软件。
