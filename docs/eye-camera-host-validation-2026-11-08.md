# AV-E6d 摄像头接入眼部与共同媒体线程

日期：2026-11-08；基线 `8e89f19`；分支 `feat/windows-eye-output-20261107`。
本轮仅源码、类型检查及独立 CI 合成验证；无真实摄像头/麦克风、播放、SDK、
设备注册、安装或防护改动，不恢复/改名运行被隔离的本地测试程序。

## 假设与决策

假设：固定的原生摄像头绑定可将原始 QPC/BGR 帧交给同一次授权的眼部流，并与
原声输入/两路输出共同启停；错来源、迟到帧和清理失败不穿过关闭的入口。
决定摄像头原生接口和主进程生命周期能否供后续主窗显式开始使用。
旧帧交付、错误来源、回调期间代码卸载、清理未完报告 idle、PCM/QPC 改写或无法
解释的回归失败均为停止条件。合成进程链不替代 SDK、真人、设备、安装与会议证据。

## 变更

- 可选 `TingXianCameraInput.dll` ABI 1；固定结构大小、代次、标志与字节数，
  显式来源/意图、所有者线程和读出失败清零。DLL 未加入应用安装包。
- 摄像头回调在交给 MF 前，将承载回调的可选代码模块固定到进程结束。
  [GetModuleHandleExW 官方说明](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getmodulehandleexw)
  说明 `PIN` 的进程寿命语义。回调析构事件不能证明最后一次 Release 栈已返回；
  不能据此提前卸载代码。本策略只保留小型代码映射，设备、帧和 MF 会话仍需清理，
  不固定 NVIDIA SDK/模型。代码更新须在进程退出后生效。
- Rust `camera` 绑定在原生线程验证摘要、打开文件锁、实际模块路径和 ABI，
  对帧保留原 QPC/序号/gap。固定 BGR 容量，无帧就绪时不分配大缓冲。
  `revoke` 与停止/状态/销毁分别记录，无法证明销毁时保留库与文件锁并禁止重启。
- `Host::start_media` 显式接收摄像头、本人麦克风和眼部 feed。feed 与校正 reader
  必须属于完全相同的 controller/lease；检查通过前不创建输入设备。
  实际原始帧只进入 `QpcStreamFeed`，校正结果沿既有共同时间线/输出路径交付。
- 每轮最多取一张摄像头帧，既有单帧输入槽、眼部有界 writer 和共同音频容量保留。
  音频仍按原包/原时间处理，不把正常语音改成视频式最新块替换。
- 两输入由同一个退出 guard 管理；正常退出和异常展开都先关闭流/视频及摄像头
  交付，再清理麦克风、等待摄像头 Flush/Shutdown，最后回收输出。停后才返回的
  摄像头帧仍要重新过关闭检查。清理失败保持独立结果及重启阻塞。

仅增加原生入口，未接 WebView/主窗开始操作。展示窗无采集/模型/Key 权限。
摄像头当前硬件源、720p30 的边界不变；软件源、iPad、真实颜色/时钟与帧率待测。
