# AV-E6b 原声接入共同媒体线程

基线 `be5a8d0`，独立 `feat/windows-eye-output-20261107`。完整目标仍为原始音视频经
眼部校正、共同时间轴送往两种会议端点；本轮不启动真实采集、不升级应用或修改防护。

## 决策与实现

假设：固定原生输入组件可在共同所有者线程保留整包原声、设备位置与原 QPC，并在
退出确认前与输出共同退役。决策价值：为已有媒体 Host 接通原始输入能力，避免借用
丢失设备时间的 ASR 回调。停止条件：需要未授权采集、错源/伪造时间、缓冲无界、
清理失败被隐去或绕过防护。影响原生绑定、Host 生命周期、时间线准入及验收。

- 新增 Rust 输入绑定，使用构建固定摘要、文件占用及实际模块路径核对加载自有
  `TingXianAudioCapture`，校验 ABI/结构长度/状态。实例不可跨线程移动；默认无行为，
  不接受网页传入 DLL/摘要。读取后保留原设备首帧、100 ns QPC、PCM 和静音/不连续标记。
- `Host::start_captured` 需要明确原生授权及当前代次；本人端点由原生选择传入，
  禁止回采的端点直接取自该输出配对。输入工厂在媒体线程创建；检查、准备、启动、
  读包、停止、重置和销毁均归该线程。此入口尚未接成可点击的主窗启动功能。
- 原声直入同线程时间线，没有第二条采集线程或额外输入排队。完整包上限 4800 帧
  （48 kHz/100 ms），时间线总上限仍为 9600 帧；输出窗口上限仍为 960 帧。
  不拆包制造采集时间，不用覆盖上一包的方法处理语音背压。既有人工合成入口维持
  原 2400 帧/16 包上限；采集所有的会话拒绝该入口注入其他 PCM。
- 首包原始不连续标记保留并计数；仅新时间线无前驱时接受，后续标记仍故障并清空。
  输出等待集加入采集事件，停止事件继续优先，借用句柄存活覆盖完整等待。
- 输入异常撤销共同输出；停止前先撤销视频呈现，再清理输入与两路输出。输入停止、
  状态和销毁结果独立保存；清理失败锁住后续会话，不能报告正常退出。异常展开先
  清理采集，再等待输出/眼部源退役。旧代次及外部设备排空屏障不因接线被解除。

时间戳与整包规则依据微软 [GetBuffer](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer)，
等待句柄生命周期依据 [WaitForMultipleObjects](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitformultipleobjects)。
API 契约及容量上限不证明真实设备时钟精度、处理延迟或会议同步。

## 验证

D 盘源码外证据 `artifacts/2026-11-08/audio-host-001/`。本机只运行 `cargo check --tests`
类型检查；初次通过但有新增多余 unsafe 警告，修正后仅保留原工作区配置警告。没有
生成/运行此前被 360 清除的测试 EXE，没有恢复隔离项或改名/换路径尝试运行。

新增独立 CI 回归覆盖：真实 DLL 拒绝许可与未知设备、摘要不符；整包数据/大 QPC
精度/原始标记；代次/边界/异常字段；与合成眼部帧共同输出原声；检查/准备/启动/读包/
清理故障；阻塞清理期间不得宣称退役；未暴露输出的三次生命周期。实际成绩待 CI 核对。
这些回归保持已有断言，不把类型检查等同执行通过。

尚未验证：真实 WASAPI 采集、USB/蓝牙/拔插与权限、停止的 500 ms/1 秒门槛、实际
输入转输出的长时钟漂移、虚拟端点排空恢复、主窗开始交互、新安装器、正常防护下
实机兼容、飞书接收端 P95 ≤100 ms 及长期会议。没有新 SDK/模型/第三方二进制入库，
没有音视频外发；教育、实时辅助及数字人冻结边界保持。
