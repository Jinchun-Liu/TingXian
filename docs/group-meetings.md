# 听弦的多人发言规则

模式按「提问方人数 → 作答方人数」命名。遇到轮流主持、汇报、自由讨论交替的会议可选复合会议。模式与点名称呼保存在本机，标准工作区和高级工作区共用。

| 模式 | 常见情况 | 自动回答开启后的行为 |
| --- | --- | --- |
| 一对一 | 一位面试官与一位候选人连续追问 | 对端每段完整发言均可触发，延续原有流程。 |
| 多对一 | 多位评委向一位候选人补充条件 | 所有对端完整提问均可触发，生成时保留最近讨论和当前问题。 |
| 一对多 | 面试官按姓名、编号轮流请候选人发言 | 识别自己的称呼后提醒，其他候选人的发言只留在转写和上下文。 |
| 多对多 | 多位面试官与候选人自由讨论或重新分配问题 | 默认只记录，直接点名再回答；不会将同一对端通道的声音识别成具体个人。 |
| 复合会议 | 主持、汇报和讨论交替，参会者可能临时被要求解释或决定事项 | 使用同一点名规则，建议区分已定结论、他人提议和待确认事项。 |

**为什么保留所有发言**　牛津大学职业服务介绍的测评中心可以在小组练习、展示、个人面谈之间切换。小组题常常承接其他人的观点，因此未点名的发言仍有上下文价值。微软的共享会议室转写也说明，若无说话人识别，音频可能统一归到会议室。听弦使用本机的系统音频与麦克风来源区分本人和对端；称呼用于判断谁被叫到。[牛津大学](https://www.ox.ac.uk/careers/careers-guidance/job-search-and-applications/assessment-centres) · [Microsoft Support](https://support.microsoft.com/en-us/teams/calls-devices/use-microsoft-teams-intelligent-speakers-to-identify-in-room-participants-in-a-meeting-transcription)

**通话前**　在左侧选择模式，只填可能用于直接称呼你的姓名、昵称、英文名或候选人编号，可用顿号分隔。多人模式留空时只记录；共同称谓如“老师”容易同时指向几个人。选择一问一答时，未点名的讨论保留在完整记录里。

**通话中**　“小林，请解释方案”在整段定稿后提醒并进入回答队列。“小林。”先提醒，12 秒内紧接的“你怎么看？”可生成一次建议。窗口只接续一段；本人开口、切换模式或重新开始采集会结束接续。提到“小林的方案”、引用别人的话、其他人发言或自己的麦克风转写不会单凭名字自动回答。对端混音、同名、口音、叠音和未配置的称呼仍可能误判；漏点名时可从原始转写选中该句并手动发送。暂停自动回答后仍可看到点名提醒。拆分窗口时两侧均能看到提醒。

**验收边界**　自动化检查覆盖五种路由、整段复核替换、分两句点名、过期、重复、英文词界、引用、本人语音和模式切换。真实多人通话的误报率、漏报率和延迟仍需用人工标注评估。
