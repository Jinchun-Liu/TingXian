# 听弦 PRD v2.2 面试学习与模拟训练

日期：2026-11-07。文档版本为需求增量版本，不等于软件发布版本。面向产品、开发、内容贡献者与验收人员。

听弦保留实时交流辅助及现有开发目标，在同一产品中增加会话复盘、教练练习、模拟面试和复练安排。已有资料、真实发言和学习记录相互关联，AI 建议始终与本人实际表现分开。软件及基础产品继续免费、开源；用户自行选择的模型服务费用另计。

本次交付是可供主进程实施的 PRD、启动指令和开源研究资料，不表示教育功能已实现。首轮以 EDU-M1 会话复盘与单题重答为实施边界，不等待摄像头、TTS 或全类别题库就绪。

## 1 需求决定与既有约束

### 1.1 已确认的产品决定

- 教育能力叠加在现有功能上，不将听弦改造成仅有题库的独立应用。
- 保留本地转写、实时建议、本人上下文、三路不同问题并行、背景资料、截图、五种人数模式、拆窗和本地眼部路线。
- 增加可单独使用的练习价值：没有真实面试、会议或摄像头也可以学习。
- “全类别”是可扩展覆盖目标；各类别按内容、评测和真实使用证据逐项开放。
- 教学反馈以用户实际作答为证据，不替用户编造项目、职责、业绩或经历。
- 继续沿用听弦名称、品牌图标、免费开源和用户自备 API 的原则，不引入强制账号、订阅或付费转化指标。

### 1.2 与旧 PRD 的关系

PRD v2.0 的 R01—R09 和 v2.1 的 R10E、R10F、R11 边界继续有效。本文件新增 EDU-01—EDU-12，只规定学习场景；不会更改实时辅助的来源判定、回答节奏或模型路由。

本地眼部仍为可选模块，脸部只保留低优先级禁用入口和接口；旧完整数字人、照片注册、口型、TTS、虚拟麦克风及全程代理维持原冻结/后置状态。文字 AI 面试官不需要重新启用这些模块。

教学策略按会话模式加载，不能把“一次一个提示、先不显示答案”的策略套到原实时辅助。三路 API 仍代表不同问题分配不同模型并行处理，不改成同题三个模型相互评价。

## 2 用户价值和范围

主要使用者为成年求职者、在校大学生、转岗者，以及后续加入的职业辅导者。首轮解决三个问题：不知道回答哪里不足、看懂参考答案却说不出来、练习后无法确认是否能够独立迁移。

用户能完成一次具体任务：选一道真实或合成问题，保留自己的初答，获得有依据的反馈，再独立重答或回答一道变式题。功能成功以任务完成和可观察的改进判断，不以生成篇幅或 AI 自评分增长判断。

| 范围 | 首轮取舍 |
| --- | --- |
| 当前实时辅助和眼部开发 | 保留目标与原验收门槛，教育模块可独立禁用 |
| 会话复盘、逐题反馈、重答 | EDU-M1 必须交付 |
| 教练练习、文字模拟面试 | EDU-M2，在 M1 数据与隔离契约通过后实现 |
| 通用行为面试、软件与 AI 技术面试 | 首批内容包；不声称代表所有岗位 |
| 其他职业、管理、销售、产品、升学、公考等 | 相同接口扩展，内容与专家核查逐包完成 |
| 教师端、班级、共享课程、LMS | EDU-M4 后置，不在首版建立多租户服务 |
| 语音输出、数字人面试官 | 不是教育首版依赖，原冻结范围继续有效 |
| 自动执行用户提交的代码 | 不做；后续需独立沙箱，不能在宿主直接执行 |
| 就业保证、录用概率、人格诊断 | 不作为产品输出或验收指标 |

模拟面试与实际面试规则分别呈现。教育能力提供独立用途，不意味着任何实际面试都允许实时辅助。

## 3 三种使用模式和共同复盘

| 模式 | 主要行为 | 答案与反馈 | 记录规则 |
| --- | --- | --- | --- |
| 实时辅助 assist | 沿用现有采集与建议链路 | 保持答案先流式、纠正问题后显示 | 真实发言、AI 草稿、纠错分别保存 |
| 教练练习 coach | 围绕一个目标尝试、提示、补教、重答 | 可请求方向提示、概念解释或完整示例 | 记录实际帮助及是否看过解答 |
| 模拟面试 mock | 按岗位、经历、难度和时长连续提问追问 | 默认结束后反馈；过程中不显示参考答案 | 独立作答与中途求助严格区分 |

“复盘”是会话或题目的操作，不是第四种采集模式。用途、人数模式、资料包和学习模式是不同维度，不能塞进一个大下拉框。模拟面试官是 AI 角色，不伪装成真实外部说话人。

会话中切换模式时，先完成保存或暂停、取消旧任务并递增代次。保留原始记录，建立关联的新阶段；不能把已提示的尝试改标为独立测评。没有活跃任务和未保存内容时，模式选择不增加多余确认。

## 4 教学流程与内容包

### 4.1 最小学习循环

确定一个目标 → 用户先尝试 → 找出首个关键缺口 → 按需帮助 → 用户再次完成 → 换题撤去帮助 → 留下复练任务。

目标写成可观察行为，例如“区分超时与事务失败，并提出核验步骤”，而不是“掌握分布式系统”。用户已经证明会做时可跳过教学；用户卡住时允许简短明示教学，不能无限反问。

提供完整示例后仍可学习，但该题标记“已看解答”；后续独立表现必须在未暴露关键答案的可比新题中取得。无回应、未提交和 AI 自动补写都不能算学习完成。

### 4.2 类别扩展

通用引擎管理会话、资料、提示、评估和恢复；类别包提供岗位事实、目标、题目、追问规则、评分锚点与参考资料。内容包的状态为 draft、reviewed、pilot、validated、retired；未达到对应证据的类别不显示“已验证”。

首批内置包：

- general-behavioral：自我介绍、项目/经历说明、协作、冲突、失败复盘和岗位动机。参考答案只给结构与已确认事实，不补造业绩。
- software-ai-foundations：API 契约、测试、数据语义、重试、幂等、事务边界、排错及表达。代码先作静态讨论，运行测试后置。
- generic-custom：用户指定岗位与来源，生成草稿题组，始终标明未经过专业审核。

销售/客户成功、产品/运营、管理、财务、设计、升学、资格考试等逐包扩展。特定考试、职业规范和专业标准须记录地区、版本与来源核对日期，不能从通用模型问答直接推定已覆盖。

## 5 EDU-01 会话复盘和证据选择

会话历史及单题菜单提供“复盘”。用户选择题目、本人回答、岗位/目标和允许使用的资料，预览后发起生成。默认不上传整个会话库，不启动新采集。

来源支持已保存会话、手动输入和合成演示。原会话只读；教育记录保存来源 ID、修订和哈希，不修改原回答或覆盖正式历史。

旧会话缺少本人回答时，显示“缺少本人作答”，可以开始一次新练习；不能拿 AI 草稿充当本人回答。旧版本无法判断用户是否看过建议时标记 assistance_level=unknown，不能用于独立能力分数。

生成结果包含：题目要求、已展示的能力、一个优先改进点、证据位置、下一次练习动作。默认只突出有用反馈，完整评分和资料引用可展开。

## 6 EDU-02 反馈与评分

### 6.1 最小反馈结构

每条反馈包含 criterion_id、判断、answer_revision、evidence_refs、改进动作、可选 source_refs，以及是否能评分。证据引用必须定位到真实输入片段；不存在或哈希不匹配的引用不允许当作已核验依据显示。

区分回答缺口、知识错误、来源冲突、转写可能错误和证据不足。用户可纠正自己的转写或对反馈提出异议；产生新修订后，旧评估标为过期，重新生成不得覆盖旧证据。

### 6.2 评分标尺

采用按维度的 0—3 级行为锚点，不默认生成笼统的百分制总分。

| 状态 | 含义 |
| --- | --- |
| 0 | 在有效作答证据中尚未展示该题要求 |
| 1 | 展示部分关键点，存在明确遗漏或错误 |
| 2 | 在该题条件下完成必要解释和步骤 |
| 3 | 除必要内容外，能说明边界、取舍或迁移 |
| N/A | 此题不评价该维度 |
| evidence_insufficient | 输入或依据不足，不能计为 0 分 |

通用维度为回应题意、结构与表达、证据具体性、逻辑与取舍；专业正确性由类别包提供锚点，不能强制套用到所有题。不得从口音、语速、眼神或表情推断诚信、人格、情绪或录用概率。

反馈需要支持合理的不同解法，不以与范文逐字相似作为正确标准。参考资料冲突或专业依据缺失时保留不确定性，可提供待核查问题，不编造“权威答案”。

模型评估是可质疑的辅导意见。教育效果验收另用人工盲评和新题表现，不能让同一模型的分数上涨自行证明有效。

## 7 EDU-03 重答与 EDU-04 教练练习

重答建立新的 attempt_id，保留初答、帮助记录和版本。用户可选择原题重答或一道能力要求相近的变式题，默认不同时显示变式题的参考答案。

教练提供三个清晰动作：“给我提示”“解释这个概念”“查看示例”。先用最小帮助，默认连续两次同类提示仍未推进时，提供换一种解释、缩小目标或结束的选择；不能把反复追问作为强制流程。

可选教学策略：

- 苏格拉底式提问：每轮聚焦一个关键判断，允许用户退出或主动查看解释。
- 讲给初学者听：用户解释概念，教练追问术语、因果、例外与类比边界。
- 对照讲评：对照已提交初答和参考，先处理第一个实质缺口，承认不同的有效路线。
- 职业情境任务：在真实工作约束下解释操作顺序、验证方法与交接。
- 撤去帮助的新题：保持目标和难度可比，记录帮助是否真的减少；不能只改几个词后重复原答案。

每条 AI 示范均标为参考，不能自动写入用户事实库。用户“收藏”也不改变 provenance；只有明确确认的个人事实才能按既有背景审阅流程进入正式资料。

## 8 EDU-05 模拟面试

配置只保留岗位/类别、目标层级、语言、时长或题数、选用资料。默认文字输入和文字提问，无摄像头、麦克风或 TTS 副作用。

问题来自已选择内容包和资料快照。每轮只呈现一个主问题；允许一个问题包含必要子项，不能机械拆散复杂题。追问基于用户刚提交的回答，不能引用未说过的 AI 建议。

按预先确定的能力覆盖表控制节奏，防止一直追问同一细节。默认标准轮次建议 6 个主问题、每题最多 2 个追问，用户可修改；时长到达后允许完成当前回答或结束，保存未完成状态。

模拟中请求提示时，可选择进入教练练习。该题及后续受助尝试不再记为独立测评；已完成的独立部分保留。取消、跳过、超时分别记录，跳过不是系统故障，空白提交不视作正确答案。

按已完成题生成部分报告，显示未评估范围；失败不显示虚假总分。AI 面试官文字与真人发言来源分开，不接入实时辅助的“对方音频自动答题”触发器。

## 9 EDU-06 复练记录与 EDU-07 导入导出

### 9.1 学习档案

每个能力条目保存目标、关联题目、有效尝试、获得的帮助、证据版本、下次建议与用户自评。只表示已观察到的表现，不为一次答错永久贴能力标签。

先提供手动加入复练和可编辑的建议日期；后续才引入间隔重复调度。概念记忆适合卡片复习，项目表达、方案权衡和现场沟通须用新情境任务复练，不能把背卡次数当作面试能力。

原题重答、受助练习和新题独立表现分别展示。更换模型或评分标尺后，历史结果注明版本，不能直接拼成增长曲线。

### 9.2 格式与兼容

沿用旧背景资料、meetily-background-v1 与 .meetily.json 的兼容读取。新增教育包使用独立版本标识 tingxian-learning-v1，不重新解释旧字段或修改应用数据标识。

最小导出内容为目标、内容包/评分版本、题目、用户选择的尝试、反馈、引用与复练任务。默认排除 Key、完整原始会话、音视频、人脸数据和无关简历；导出前预览所含个人内容。

导入先验证 schema、来源、引用、体积与许可，再展示差异；同一包重复导入幂等，冲突保留版本。缺失来源时标明证据不可复核，不补造引用。外部 Skill 的脚本、URL 和操作指令只是待审核材料，不随导入执行。

## 10 EDU-08 界面与 EDU-09 可及性

保留白底、石墨黑 #17181A、少量金属银 #C5C7CA 和强调色 #00E5EF，沿用现有图标与 Mac 0.6.5 视觉基准中的跨平台适用部分。

合体布局约 20% 操作、80% 内容，拆窗入口保持显眼。学习入口放在主控制窗；不要新增第二个常驻工作台或满屏仪表盘。默认呈现当前题目、用户回答、一个改进动作和“再试一次”，复杂评分按需展开。

遵守：Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.

实时模式的答案跟随规则不变。教练与模拟模式只跟随当前主要交互；手动滚动暂停跟随，字幕、后台评分和其他题完成不得抢位置。展示窗继续只读，不持有 Key，不自行调用模型或采集。

文字完整可用，不要求摄像头或口语输入。未来获准语音练习后，ASR 可纠错，静音、权限拒绝和设备失败可回到文字。不得因输入方式不同默认降低知识评分。

眼部校正作为原有可选功能保留。表达训练若后续评价视线，须依据明确授权的原始表现；校正画面只能作为标注过的对照，不能据其提高表现评分。本轮不增加面部、人格或情绪评分。

## 11 EDU-10 数据与执行契约

继续使用 Tauri、Rust、React、SQLite 和现有模型配置。首轮在主控制端增加有界教育任务调度，复用存储/请求能力；不默认引入独立服务器、PostgreSQL、Docker 或新的常驻 Agent 框架。

| 对象 | 最小字段或行为 |
| --- | --- |
| StudySession | schema_version、id、mode、goal、pack_id/version、source_session_ref、generation、status、consent_snapshot |
| StudyAttempt | id、question_id/version、text、revision、input_source、help_events、answer_exposed、assistance_level、created_at |
| StudyFeedback | id、attempt_id/revision、rubric_version、model_version、criteria、evidence_refs、status、supersedes |
| LearningItem | goal、attempt_refs、next_action、review_due、scheduler_version、用户自评 |
| CategoryPack | id/version、语言、领域、目标、来源及许可、题目、追问规则、评分锚点、review_status |
| EducationTask | task_id、session_id、generation、输入哈希、状态、预算、取消标识、输出修订 |
| SkillDescriptor | id/version、用途、适用模式、来源 commit、license、依赖、允许能力、输入输出 schema、回归样例 |

provenance 至少区分 actual_self_speech、typed_self_response、ai_draft、ai_interviewer、hint、reference_solution、external_source、synthetic_fixture。assistance_level 至少区分 independent、prompted、worked_example、unknown；两者不可混用。

教育任务状态采用 queued → running → completed/partial/failed/cancelled；暂停与等待用户输入单独表示。停止、清空、模式切换、资料切换或输入修订后更新 generation，拒绝旧任务回填。恢复历史只恢复内容和偏好，不自动采集或重发请求。

模型重试最多 2 次且可取消；没有语义幂等支持时，不把“服务商超时”解释为没有产生费用。反馈写入由 task_id、attempt_revision 和 generation 去重，重放不得重复增加复练任务或评估计数。

首轮同一教育会话最多一个交互生成任务及一个可取消的后台评估任务。它们不能占满实时辅助三个问题位置；实时会话活跃时教育后台任务排队或显式暂停，不另建无上限请求池。

## 12 EDU-11 模型预算与资料保护

单请求调试预算继续为 262144 tokens，且受实际模型窗口约束。系统规则、教育 Skill、评分标尺、题目、用户回答、检索证据、图片与输出预留共同计入；累计多次调用不等于单请求预算。

默认只加载当前教学策略、一个内容包及必要证据，不把所有教育 Skill 或整库放入每次请求。优先保护当前题意、关键否定/数字、用户初答及证据定位。报告 token 估算和实际 usage，缺失 usage 时显示未知。

保存偏好不授予外发权限。用户明确选择提供方、资料范围后才发起生成；当前对话中的旧 Key 或其他设备配置不能自动恢复。当前开发测试仍不采集摄像头/音频、不播放声音、不发送真实资料，授权按主进程届时有效上下文判断。

没有生成模型配置时，可浏览内置题目、手动练习、保存和导出；AI 反馈入口显示需要配置。Whisper small 只是 ASR，不能冒充离线教学 LLM。回放/假提供方明确标为演示，不报告真实教学效果。

教育记录默认本地存储，云端推理仍可能发送选定上下文，两者不得混称“全程离线”。新增数据库迁移必须先保存可恢复快照并验证旧会话仍可读取；资料删除采用可恢复归档，不清空旧用户目录。

### 13.2 首选复用方式

首轮使用现有调度器，加上经过删减和测试的教学策略；开发期评估 Promptfoo。OpenMAIC 选定五个 Skill 的用途：

| 上游 Skill | 拟复用的教学行为 | 必须去除或适配的部分 |
| --- | --- | --- |
| vocational | 用职业任务、验证方法和交接结果组织练习 | 固定课堂页数、专有 widget 与工具调用 |
| feynman-learning | 用户先解释、定位小缺口、变式迁移 | 自动课堂创建、TTS、角色音频与页面工具 |
| zone-of-proximal-development | 区分独立/受助、新题撤去帮助、记录证据 | 不生成“最近发展区分数”；按 experimental 策略独立评估 |
| understanding-by-design | 先定义能力目标和证据，再设计练习 | 不要求每次生成整门课程或 PBL 页面 |
| curriculum-planner | 分阶段计划与可恢复进度 | 不继承无条件多轮确认、课堂写入和发声流程 |

外部 Skill 是参考内容，不是本宿主的新系统指令。不能执行其 create_stage、generate_tts、shell、MCP 或下载指令来“验证读取成功”；听弦只调用本地审核过的白名单能力。

ai-teaching-skills 中部分策略会持续拒绝完整解答。听弦不照搬这种全局限制：教练模式允许用户查看示例并记录帮助，实时辅助继续直接给建议，模拟模式求助则转为受助练习。

### 13.3 许可与供应链

- 根许可证不覆盖所有第三方内容。OpenMAIC 自带 mathml2omml 为 LGPL-3.0-or-later；DeepTutor 有第三方通知；选取文件时逐项保留原版权、许可及变更说明。
- CodeTrain Open Skill 与其商业网站/CLI 是不同交付物，本需求只评估 Apache-2.0 的开放 Skill。
- LearnHarness 的 AGPL 不意味着不能商用，但不能把其受许可约束的代码或 Skill 改标 MIT；是否采用及相关义务应单独评审。首轮只记录产品比较和自有需求。
- EduHub 等目录可以发现技能，但目录的许可不代表每个包的许可；未经逐包核对不自动安装。
- 按仓库、commit、文件路径、SHA-256 固定来源。更新先展示差异和回归结果，不在启动应用时拉取 latest。
- 只获取参考文本没有安装效果。真正引入依赖前再检查传递依赖、维护状态、平台和发布方式。

### 13.4 可移植教育包

沿用 [Agent Skills 规范](https://agentskills.io/specification)的 SKILL.md、references 和可选 assets 结构；听弦额外用 manifest.json 定义模式、权限、来源、输入输出 schema 与测试样例。自定义字段放在合法 metadata 或侧车清单中，不假定任意宿主都支持自定义工具。

首版只允许声明式教学内容。包含脚本、未知工具权限、路径穿越、符号链接、异常压缩比、未声明许可证或外部下载行为的包进入拒绝/待审状态，不因正文声称安全就执行。

Promptfoo 如后续引入，开发环境设置 PROMPTFOO_DISABLE_TELEMETRY=1 和 PROMPTFOO_DISABLE_UPDATE=1；不使用分享上传。远程模型或评审模型的请求仍需对应授权，不能因评测器在本地运行就称数据不外发。[官方遥测说明](https://www.promptfoo.dev/docs/configuration/telemetry/)

## 14 验收矩阵与完成定义

每项记录 commit、内容包/Skill/模型版本、输入摘要、步骤、预期/实际、证据、恢复及未测项。首轮不新增无决策价值的大规模模型排名。

| 编号 | 范围 | 必要结果 |
| --- | --- | --- |
| EDU-T01 | 原功能回归 | 实时建议、三题并行/第四题排队、本人仅入上下文、阅读跟随及展示只读保持 |
| EDU-T02 | 旧资料兼容 | 旧会话/背景包可读；升级失败可恢复；教育记录不覆盖原会话 |
| EDU-T03 | 来源隔离 | AI 草稿、面试官、示范均不当本人事实；帮助未知不标独立 |
| EDU-T04 | 引用与修订 | 固定样例的引用可全部定位；错引用被拒绝；修订后旧评分过期 |
| EDU-T05 | 重答闭环 | 初答、反馈、重答分别保存；重启后可恢复，重复请求不重复记账 |
| EDU-T06 | 模式与求助 | 实时不被教学策略阻拦；模拟求助保留受助标记；旧任务不回填 |
| EDU-T07 | 错误路径 | 429、超时、断网、空输出、非法结构、磁盘失败均保留输入且可恢复 |
| EDU-T08 | 预算 | 所有实际提交符合模型窗口和 262144 上限；usage 未知不填 0 |
| EDU-T09 | 内容质量 | 两个首批包的来源、评分锚点、合理替代答案及专业边界可复核 |
| EDU-T10 | Skill 导入 | 未知版本、缺许可证、越权脚本、注入指令和重复导入按规则处理 |
| EDU-T11 | Windows GUI | 中文路径、窄窗、字号、拆窗、保存重启及禁用学习模块后原功能正常 |
| EDU-T12 | 模型与学习效果 | 真实模型、人工复核和迁移表现分别报告，不能由假提供方替代 |

EDU-M1 必测 T01—T08、T11 的相关路径，以及 T09 的初始内容审查。T10 随导入功能上线；T12 中真实模型与学习效果只在条件具备后执行。没有真实模型授权时，功能保持内部开发/演示状态，报告明确待测，不伪造验收。

题目种子采用原有合成 StockMarketAgent 场景：契约测试、JSON Schema、null/0/缺失字段/空串、租户与幂等键、事务已提交但响应超时、重试和并发。必须区分软件故障演练与本人真实经历。

模拟模式的参考答案不能提前进入可见 UI、展示窗或普通导出快照。文字回复的确定性契约可用假提供方验证；开放式教学质量必须用真实模型和人工样例复核。

## 15 有决策价值的实验

以下是待执行的小规模实验设计，不是本轮结果。涉及真人、外部调用、费用与资料时先取得对应条件；不为填表穷举全部模型和岗位。

| 实验 | 假设与决策价值 | 停止条件 | 影响的产物或结论 |
| --- | --- | --- | --- |
| EDU-E1 证据复盘 | 现有数据可生成可定位反馈并完成重答；决定是否进入教练模式 | 来源污染、引用虚构或保存损坏立即停止扩展，先修根因 | M1 数据契约和发布门槛 |
| EDU-E2 教学策略 | 分层帮助能改善新题独立表现；决定默认采用哪一种策略 | 预先限定同一领域 10—15 名自愿成人的小试点；完成上限或发现明显误导即停止，不能反复刷分 | 策略选择，仅是试点线索 |
| EDU-E3 编排依赖 | 现有调度足以支持暂停恢复；只有不足时替换 | 先用现有调度完成一条恢复链，若满足需求即停止框架对比 | 是否引入 LangGraph 等运行时 |
| EDU-E4 类别扩展 | 同一引擎加独立评分包能支持第二类别 | 没有专业来源或审核者时停止宣称已验证，不批量铺开 | 内容包接口与开放范围 |
| EDU-E5 首次使用 | 无摄像头、无账号仍可完成题目练习与保存 | 发现必须配置无关依赖或存在基础安装阻塞即先修复 | 首次体验与依赖边界 |

EDU-E2 先固定同领域可比前后题、盲评标尺和帮助记录，避免仅用重复原题或同一 AI 自评。样本小、有练习效应和自选偏差时，不据此宣称普遍提高面试通过率。原有实时辅助对照不需要收集真实招聘结果。

| 阶段 | 交付 | 出口 |
