## 恢复草稿实现记录（2026-11-06）

- 每秒合并变化写入独立 SQLite 草稿，正文、未发送输入、本人输入、用量和来源随快照保存。意外中断可能丢失最后一个检查点之后的内容；不承诺零丢失。
- 每次主窗口挂载使用独立 ID；启动只读目录，用户选择后才恢复正文。恢复将未完成请求改为已取消，关闭采集与外发授权，不重放请求或增加调用数。
- 退出先停止采集/请求，再等待最终草稿写入；写入失败保留窗口并显示重试。磁盘满不会每秒重复写入。
- 全量清空先归档草稿并核对可恢复副本，然后在同一事务删除并提升 epoch；迟到写入失败。退出的临时清理保留草稿。单份 16 MiB、总计 128 MiB/200 份，超过时保留旧稿并提示。
- 可复现页面夹具：构建 frontend 后运行 `node scripts/build-interview-recovery-fixture.cjs <新目录>`，只在 localhost 提供合成 IPC，不连接用户数据库或模型。普通/高级工作区均已通过 Chrome 可见恢复验证，布局保持操作在左、正文在右。
- 尚未安装本分支，不把浏览器/IPC 测试记为 Mac 实机长会议验收。
