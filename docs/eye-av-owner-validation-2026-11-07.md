# AV-E4 原声与校正视频共同控制

基线 `00e25a1186fab0eba3925d1c0e4a644bfa524b76`，分支
`feat/windows-eye-output-20261107`。接续 [异步视频桥接](eye-video-bridge-validation-2026-11-07.md)，
遵守 [AV-SYNC-20261107](eye-av-sync-scope-2026-11-07.md)。本轮仍是原生组件与合成媒体
验收，不是主窗口、安装版或真实会议闭环。

## 实验与决策

假设：设备时钟票据、共同时间线和异步视频入队确认可由同一个所有者串联；视频未
确认时不提交对应原声，单路失败共同撤销，未知排空不能靠重建对象或进程绕过。
决策价值：判断是否具备接入主窗口/真实设备准备的基础，找出时序与恢复的剩余门槛。
停止条件：过期/错误确认当成功、旧声音复播、无界缓存、屏障绕过或意外设备操作，
立即停止相关测试并定位，不用重复相同失败填验收表。

## 实现与不变量

- `crates/video-worker-control/src/joint/` 的 `JointOutput` 直接持有实际音频/视频桥、
  Timeline 和 sinc renderer，未增加 UI 启动命令。显式意图须覆盖两路；不恢复输出。
- 视频 ready 后启动音频（20 ms 静音预充），两次时钟观测后预约，预热超过 18 ms
  即故障。每次 480 个原声样本，只有一个 pending 窗口（数组上限 960）；先提交视频，
  精确 `Admitted` 后提交对应 PCM。没有第二个在途窗口。
- 时间线锁内仅有界 PCM/NV12 复制，等待/设备写入/清理/join 在锁外。停止信号在等待
  集合中优先，5 ms 有界等待检查期限。提交前须剩余 2 ms，原生层再次检查设备消费
  位置与期限。迟到、拒绝、未知入队、错误源、时钟或写入故障共同停止。
- 音频故障回调在音频清理前立即撤销视频；该能力随视频销毁变为无操作，不能调用
  已卸载 DLL。不回退原画面/真实麦克风。准备失败也返回各路清理结果。
- 停止清空 Timeline/pending，保留各路结果。两个独立端点不是原子事务：视频可能
  已被下游接收，随后音频写入仍可能失败；共同撤销不能撤回已收/已发的片段。

### 持久重启门槛

准备端点前独占打开原生配置的稳定路径，写标记并 `sync_all`；父目录句柄禁止路径
替换，拒绝重解析点、多硬链接、并发打开。非空/损坏/部分记录均为未知排空；新对象
与进程不自动清除。未暴露的空文件可重开。标记仅含协议、generation、进程 ID，
没有媒体或设备标识。

**本阶段没有清除/恢复 API。** 视频/真实音频后端尚不能证明下游排空，本地 stop
成功也继续阻断。这是暂时保护边界，不能作为可反复使用的稳定版交付。必须先实现
并验证端点释放/下游排空或受支持的恢复协议，再提供恢复；不能删标记、换文件名、
改 profile 或用布尔“已排空”绕过。

主窗尚未绑定稳定 profile 路径，调用契约要求同一应用输出权限固定一个路径，不由
webview、设置恢复或每次会话产生新路径。这不防御同一用户主动篡改文件。测试证明
进程直接退出后记录保留，没有断电/内核崩溃持久性实验。
