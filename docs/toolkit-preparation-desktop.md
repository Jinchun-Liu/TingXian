# 桌面岗位准备回导

2026-11-07，接续7a1d935的P2/P3。新增源码中的独立岗位准备入口；工具包0.5候选。安装版、真实模型/宿主推理和长会议仍未验收。

## 使用路径

资料与模型 → 资料库 → 岗位准备：

1. **导出整理资料**：导出已经过背景整理、当前有效且未被排除的来源，以及当前本人修订。普通文件索引尚未整理的内容不包含在此范围；原文件不变，不发送网络请求。
2. 外部四角色工具用 `--scope` 规划与处理，在同一版本上完成离线评审。详细命令见[共享工具入口](../interview/toolkit/references/preparation.md)。
3. **导入准备候选**：选择 `tingxian-preparation-v1` JSON，核对岗位匹配、参考资料、缺口和项目故事。展开依据可看文件名、定位、原文和单独的本人修订。
4. **保存岗位准备**：保存独立本机视图；不会写入原文、事实卡、FTS、实时模型输入或设置。**查看已保存**会重新核对来源，旧候选标示待更新。

“保存”表示保留本次准备，不代表个人经历经核实或模型质量通过。当前未提供准备视图的多版本回滚，跨块重复/矛盾仍需要Lead及三名reviewer整理。

## 来源与兼容

复用现有settings/background_library，未建新数据库或采集服务。首次导出分配本机库标识；不同库即便文件相同也不能直接互导候选。导入重核完整有效来源集合、原文哈希、提取版本、记录位置与当前本人修订，不能用外部工具自填的user_asserted制造用户确认。原背景v1/v2导入入口不变。

跨语言摘要明确使用递归键排序；与原生Doc序列化提取hash分别核对，不能混用。旧原文、提取注解、本人修订分别保存。导入至保存之间采用资料版本及已保存准备视图双重比较；任一变化拒绝覆盖。过期、排除、原文/提取/修订变化会使旧候选失效。

四个新原生命令仅主窗口可用；会话采集或生命周期锁被占用时不能进行导出/导入/保存/读取。文件入口拒绝符号链接和超过16MiB的结果，导出使用新文件名且不覆盖已有文件。前端保留错误草稿，丢弃旧请求回包，长依据分批展开、故事分页。
