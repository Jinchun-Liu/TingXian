# AV-E7c 专用虚拟摄像头线程与主窗停止

## 决策与边界

基线 `4243aa3`，分支 `feat/windows-eye-output-20261107`；前轮为实际代码与
CI 进展。本轮假设：独立 MTA 与取消监视线程可以把 AV-E7b 原生设备绑定到
具体媒体 Input；Windows Start 卡住时仍能撤销，清理失败时保留 COM 所属线程。
这决定完整主窗媒体启动能否安全复用该生命周期。断言失败先定位，不放宽断言。

本机没有运行新测试 EXE、采集音视频、播放、执行 SDK、注册或安装设备，也没有
恢复隔离文件或改安全防护。360 阻断仍是目标机执行/安装验收限制，不认定已解决。
保留其他分支和用户资料；完整数字人、声音生成和脸部替换继续冻结。

## 实现

- 新原生 `timed_video::device::host::Host` 默认关闭，创建专用 MTA；同一线程
  创建、开始、清理、销毁设备及退出 COM，独立于持续消费原声的媒体线程。
- 接收具体 `Arc<Input>`；原媒体或眼部来源关闭会使监视线程撤销此设备。
  显式停止立即发撤销；来源关闭每 10 ms 检查一次，这不是硬实时延迟承诺。
- 取消先于工厂完成时不会调用 Start；慢 Start 中取消票据仍有效。原始输入和
  设备错误互相停止，不改用原画面或物理麦克风。
- 清理失败留在活着的 MTA，保留 DLL、回调和资源，报告 `CleanupBlocked`；
  没有自动循环重试。下一次明确停止只重试清理；成功后仍保留历史错误和次数。
- `wait_idle` 以线程实际 join 为准，忙、暂停、旧代次或未知清理均拒绝新启动。
  只证明本地释放，不能清除既有外部排空屏障。
- 应用 VideoState 持有新 owner；主窗停止、退出暂停/清理、取消退出和组件检查
  同时考虑媒体与设备 owner。取消退出不恢复启动。展示窗没有新增权限。

## 验证

本机 Rust 1.99.1 `cargo check -p video-worker-control --tests --locked --offline`
通过（仅原有 workspace patch/profile 警告）。第二次检查覆盖新增实际 DLL 拒绝
路径测试；未执行测试二进制。

新增七项原生主控测试计划覆盖权限/代次/恢复、工厂阻塞中停止、来源停止取消慢
Start、媒体停止及慢清理、失败保留/明确重试、操作错误/展开恢复、实际固定 DLL
创建后取消。合成媒体使用真实 Host 与无 SDK 子进程，设备 OS 边界为内存注入；
实际 DLL 用例在 Start 之前取消，不注册设备。应用 IPC 回归新增第三 owner 的
展示窗隔离、退出暂停、取消退出不恢复和显式停止断言。CI 结果待回填。

工件在 D 盘 `artifacts/2026-11-08/device-host-001/`。保留实验声明、类型检查、
CI 日志与摘要；源码、合成、CI 安装和目标机验收分别记录。

## 未完成

完整主窗开始按钮、设备选择与注册 COM 源的可信版本固定仍未接入；本 owner 的
原生开始要求上层先校验源，不把注册路径存在当作可信。功能仍默认关闭。
实际 SDK、摄像头/麦克风、两输出、普通防护安装、外部排空、接收端 P95 ≤100 ms
与长期会议未验收。主窗停止接线不是完整音画链路交付，也不据此发布稳定版。
