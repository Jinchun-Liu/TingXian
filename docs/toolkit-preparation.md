# 岗位视图与故事卡的可移植整理路径

2026-11-07，接续 `81ea452` 的 P2/P3 实施。本批完成离线工具的输入准备、模型响应收集、来源校验和可读候选输出；当时尚未接入桌面独立导入/应用；后续源码接入见[桌面回导](toolkit-preparation-desktop.md)。不是安装版新增功能，也不是语义质量通过。

## 可运行路径

`interview/toolkit/harness.py` 新增 `preparation-plan`、`preparation-input`、`preparation-collect`。用户提供经背景工具校验的 v1/v2 包、资料库标识、目标岗位要求与当前修订/排除清单；模型按块做岗位相关性筛选和经历组织，工具负责确定性校验，不用关键词排名冒充模型筛选。

- 每项岗位要求都有个人证据匹配、参考资料或明确缺口。模型给出 direct/supporting 及理由；跨块仅按该分类汇合，不冒称完成全库语义排序。
- 故事卡分情境、任务、本人行动、结果、复盘。叙述片段引用本块 personal/evidence；practice/job/technical 只作参考。空字段必须给待补问题，不能造一个完整故事填空。
- 原文与提取注解拆开。archive v2 的 source_asserted claim 使用原文，注解另存 extraction_note；本人修订保留原引文和依据。连续修订必须接到最新记录，避免同一来源生成两条当前声明。
- 未知完成状态保持 unknown；结构化标为计划/进行中的来源不能生成已完成故事。引用位置存在不证明文字蕴含，因此所有产物始终是候选。
- 每块的哈希绑定实际记录、目标、提示/方法版本和预算。当前计划缺块会拒绝完整收集；旧块单独报告且不进入新产物；未变块可复用。分块边界改变时邻块也可能重跑，不承诺每改一文件只需一次调用。
- 输入按来源标识与原文位置排序；不按含内容哈希的记录ID重排整库。完整档案不因岗位视图裁短，未选记录保留。
- 导出 JSON、Markdown 或现有四角色 candidate。三名 reviewer 应独立读取同一版 candidate；修改后的候选不能沿用旧 hash 评审。本批仅验证结构编排，没有执行真实四角色模型。

详见[岗位准备入口和协议](../interview/toolkit/references/preparation.md)。四份角色 skill 只增加按需引用，背景执行组件仍是同一份，未创建第五角色或新数据库。

## 方法与预算

默认只用已验证方法，当前注册表的候选不会自动激活。开发对照可显式加 `--preview-methods`，加载10条相关 CV 规则和4条面经规则，包括职责/贡献/项目证据/缺口；排版、ATS、口语全套规则、32方向全文与三角色说明不进入本输入。方法来源和例外保留在离线 manifest。

模型窗口取实际声明与262144的较小值；默认单块保守输入上限32768、输出预留8192、安全预留4096，均非精确token计数。输出预留可调整；不把8192当所有高推理模型的硬性默认。超限显式拒绝，不能裁掉事实或要求。工具无网络客户端，宿主实际请求参数、用量和费用仍需宿主记录。

## 合成验证

11项新用例与10项原工具用例通过；四角色 skill frontmatter 与相对资源校验通过。包括完整要求覆盖、练习不能变经历、未知引用/跨块引用、未知与计划状态、缺块/重复结果/过期结果、用户隔离、人工修订链、来源更新、预算拒绝、候选规则开关、真实CLI往返及评审后隐藏改写。

一个四源更新案例只改一份、保持分块边界，3个未变输入哈希继续复用，1个新块替换旧块，旧响应不回填；这是可复用性证据，不是服务商调用或费用节省实测。

`measure-toolkit-preparation.py` 每档独立进程，1次预热后5次采样，p95即小样本最大值。档案构建在计时前；RSS包含Python解释器、档案和分块，不是某个函数的增量峰值。

## 当前边界

`tingxian-preparation-v1` 不能直接送进桌面背景包导入入口；不要将候选故事塞回原文/事实卡绕过格式。后续[桌面源码](toolkit-preparation-desktop.md)已提供独立回导和当前来源校验；此处保留0.4阶段测量口径。跨块故事整合、真实模型A/B、Codex/Claude Code执行与回导、安装版和长会议仍未完成。

实时按需加载与原口语策略不变，精简候选未晋级，Harness²默认关闭。35文字+12视觉冻结文件、12口语输入及其生产提示源哈希未变化。没有安装新软件、重启采集或读取真实API凭证。
