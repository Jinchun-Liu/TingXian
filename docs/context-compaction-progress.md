## 运行路径

`frontend/src/lib/interview-memory.ts` 供两个 interview 入口共用。关闭记忆时没有 AI2 请求或记忆事件表写入。开启后，完整转写前缀先串行提交原生 SQLite，收到 ACK 才更新 120 条界面 ring；partial 字幕不持久化、不触发压缩。整段 ASR 更正使用同一逻辑事件的不可变新修订。采集批次、native session、麦克风 epoch、utterance 隔离；本人发言/人工确认只作实际上下文，不触发回答。

本地失败保留队首和最多 128 个待写操作，暂停自动回答与采集，显示未保存并允许重试。溢出明确报错，不能宣称完整历史已保存。256 个修订工作集与 120 条显示缓存都不是原文数据库；更早原文仍在已有会话数据库。

`frontend/src-tauri/src/interview_memory.rs` 由主窗口持有。AI2 使用独立 `compaction` 用途与 Key，不占 answer-2；保存配置不会发请求。固定文字自检是单独、显式且标注可能计费的动作，不启用记忆或认证长窗口。所有新增记忆 IPC 拒绝展示窗口，展示窗不获得凭证或后台任务权限。

每 5 秒仅在当前发送许可有效、没有待写失败且前台空闲时尝试调度。默认至少 8 条尚未覆盖的已结束实际发言、保留最近 12 条实际发言、60 秒冷却、每场最多 8 次；快照至多 64 事件/64 KiB。AI 答案和状态不能凑够最小发言数；失败后也必须有新的有效批次，同一快照不重复请求。候选输入保留原始来源，不读取完整背景库、四角色正文或全量领域规则。

网络期间释放会话内存锁与 lifecycle 锁。三路 AI1 各自固定 question/revision/context_version；后台成功只影响后续请求，已有流不重启。相同服务主机（或未知主机）的前台请求立即取消后台任务，不把不同 Key 误当独立配额；不同服务允许并行。跨不同域名实际共用同一限额账户尚无法自动识别，不声称具备供应商配额发现能力。

## 保真与来源

当前采用保守抽取：每项必须逐字匹配整条原文及 revision/hash，可合并相同 kind/origin/text 的引用。原始发言、本人确认、请求原题与截图条件不得省略；AI 建议/规范化问题可带理由省略。错误、取消或截断答案不能升级为完成结论。候选至少减少 256 序列化字节且达到 10% 才晋级；这不是 token 或人民币收益。

原文始终保留，不递归地只压缩上一版摘要。提交重新核对 epoch、基础版本、源修订与配置，SQLite 事务 CAS 成功后才发布。来源版本、有效日期、事实或设置变化使相关派生块失效；新请求再次核对，原始实际发言与撤回的派生资料分开。工作集最多 8 KiB 序列化旧记忆/检索内容，近期原文仍走既有轻量提示预算。

截图在既有单次视觉请求中使用，事件账本记录原题、资产 SHA-256 和“图像未持久化”说明。不会将未保存图像或 AI 提取内容伪装成原图；后续需要图中未记录条件时必须重新截屏。真实 OCR/视觉效果仍未验收。

## 预算与失败兜底

`request_budget.rs` 计量协议适配后的完整 JSON（消息封套、转义、工具与 schema），以真正 max_tokens 预留，应用上限为 262144，并与配置窗口取小。输入是保守 UTF-8 字节估算，不是供应商 tokenizer。图片未知时不能声称完整预算已通过；接近文字预算 75% 会阻止未知图片请求。

`context_pressure.rs` 使用实际发送前、最终可选裁剪前的工作集估算，不使用整场日志长度制造 200K 分支。75% 软阈值、60% 回落；以实际完整 AI2 返回时长 p95（无样本默认 60 秒）、同窗口增长速度和已知三路在途量估算压力。容量型与覆盖型都不能绕过最小增量、冷却和许可。现有上游轻量装配仍保留，因此常规路径主要靠覆盖型任务；小窗口测试不等于 256K 服务商实测。

每次发送/重试前仍有硬准入。可选旧上下文不足以缩减时明确未发送，保留当前题、事实/冲突、最新两条发言和图片；不无限等待 AI2。服务商明确返回 context_length 错误时，至多一次缩减可选历史后重试，重新计量、保留已知 usage，不产生两个答案。其他 400 不因此重试。

AI2 单次 60 秒、零自动网络重试。取消/429/超时/异常 finish_reason/无效 JSON/来源过期不晋级。进入传输前先持久化任务预留；缺失 usage 或崩溃中断保留 unknown 及预留，真实 input/output、reasoning 明细与缓存不重复累加。默认每场 200000 预留单位是已知 tokens 与未知 UTF-8/输出保守预留的控制额度，不是实际 token 总量、账单或消费授权。成功返回 usage 后按实际用量结算；发送前取消不计已发送。

协议依据：[DeepSeek 请求](https://api-docs.deepseek.com/api/create-chat-completion/)、[缓存规则](https://api-docs.deepseek.com/guides/kv_cache/)（2026-11-07 核对）。压缩改变前缀可能降低缓存命中，不能只凭输入变短声称省费。

## 持久化与兼容

复用原会话 SQLite 的四张 `tingxian_memory_*` 表，增量创建，不另建产品数据库。原文上限：每记录约 84 KiB、每会话 20000 修订/32 MiB、总 200 会话/128 MiB。检查点上限另为每版 8 MiB、每会话 128 版、总 128 MiB，逻辑上限不等于物理空间。检查点保存验证原始日志与候选，失败回滚；普通原文追加不重写整场快照。

新 v2 保存/恢复草稿固定最后原文 hash/记录号和当时检查点。恢复创建独立可写分支，旧保存时刻之后的记录不会混入；恢复重新验证来源，运行中任务标中断且不自动联网。v1 仍可恢复，但只含旧 ring 的部分原文，明确标记更早历史缺失。旧可读导出格式保持；v2 本机恢复引用不冒称跨机器全库迁移格式。

清空将四表、会话与恢复缓存纳入现有可读回废纸篓事务；归档失败不清库，epoch 阻止迟到回填。禁用 AI2 可继续现有答题；若需代码回退，先导出当前会话，保留旧数据库，新 v2 记忆不由旧版软件读取。此次没有删除用户资料、旧包或缓存。

## 测量和剩余工作

离线 3 开发/3 保留案例比较 A 短历史、B 原文检索、C 确定性抽取协议 fixture。两道短题输入相同；四道跨话题/代码案例 A 缺旧原文的 3 个指定片段，B/C 均保留 3 个。B 比 A 多 525–575 字节，C 比 B 少 150 字节；AI2 单次待发输入约 16.4–16.6 KB，再预留 8192 输出。C 没有模型推理，不能声称回答更准或整场更省。100 次 40 事件工作集选择的单案例 p95 约 0.61–0.65 ms，不含 FTS/IPC/模型/ASR。

新增磁盘测量：1000 条合成原文，追加事务+RAM 更新 p95 1.07 ms；150 条阶段 p95 4.13 ms，包含同一次运行的早期抖动。1000 条完整检查点保存一次约 62.75 ms，恢复 10 次 p95 63.21 ms，工作集 100 次 p95 0.22 ms。独立 debug 示例进程约 1.63 秒，user 1.09 秒/sys 0.49 秒，最大 RSS 16.25 MiB，数据库 757760 字节。测量包含合成夹具与运行时，不是应用后台增量资源或最大容量验收；不能推断真实首字和整场 CPU 降低。

复现入口：`cargo run -p interview-core --example context_measure --offline`；`cargo run -p interview-core --example memory_persistence_measure --offline -- /new/path.sqlite`。后者拒绝覆盖已有文件。详细 V01–V20 与真实待运行门槛见[验证矩阵](context-compaction-validation.md)。本机报告、截图和日志另存交付目录；远端 CI 以当前提交实际状态另记，不能借用 C1 的成功状态。

原任务岗位准备版本历史的桌面入口仍待接入。真实四角色推理、口语质量、费用、云 ASR、视觉、Windows/数字人与长会议等未验收项继续保留。
