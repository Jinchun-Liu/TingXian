# 听弦独立工作台：入口、数据与验收

审阅基线：公开版 v0.5.1（2691981）。两套配置分别核对：公开版入口 /interview-workspace，自用版入口 /interview；公开版 /interview 的通用、面试、学习、会议场景继续保留。以下“旧”指该基线；“现”指本分支。文中的源码路径相对于仓库根目录。

**结论。** 采集、识别与历史读取都可以在同一 Tauri 进程内工作。需要替换的是控制权和页面入口。旧页面的 api_get_meetings 实际查询本地 SQLx；它与同文件内确实请求 localhost:5167 的旧账号 API 不同。旧根布局挂载了上游 provider，也不等于每次启动都发了网络请求。

## 一次采集的真实链路

1. frontend/src/components/interview/AudioSettings.tsx → get_audio_devices → frontend/src-tauri/src/audio/devices/discovery.rs；tingxian_select_devices 在 tingxian_audio.rs 中保留原偏好，只更新输入和输出名称。系统默认用 null；非默认保留名称及 (input)/(output)。这不是修改 macOS 全局默认设备。
2. frontend/src/app/interview-workspace/page.tsx（自用版 app/interview/page.tsx）持有授权、recordMicrophone、automatic、spoken、utterances、requests；frontend/src/lib/session-commands.ts 将面板/托盘/菜单命令交给这一页。interview_audio_start 在 frontend/src-tauri/src/interview.rs 核对模型和语言，关闭原始录音自动保存，读取原设备配置。麦克风关闭时传专用禁用标记，系统通道必须成功。
3. audio/recording_commands.rs → recording_manager.rs → audio/capture 与 devices；audio/transcription/engine.rs、whisper_engine/commands.rs 和 whisper_engine/whisper_engine.rs 选中并加载本地 GGML。发行包 Resources/whisper/ggml-small.bin 由 tingxian_runtime.rs 在缺少缓存时原子补入；不覆盖已有模型。工作线程 audio/transcription/worker.rs 发 transcript-update 与 interview-utterance-end。公开版旧的 Dialogue session 标签曾绕过 small 整句复核；新会话恢复共用兼容标签 Interview practice。
4. interview-audio.ts 的麦克风 epoch 门、interview-health.ts 的音频状态、interview-scheduler.ts 的完整发言队列及 meeting-mode.ts 的称呼门决定哪些远端句子可提交。本人发言只补上下文。主窗以问题 id/修订号归并回答事件；interview_jobs.rs 与 crates/interview-core/src 下的模型、检索和供应商逻辑不依赖侧栏。未允许云请求时仅本地转写。
5. stopInterviewAudio → stop_recording({args:{save_path:''}}) → recording_commands.rs 和 audio/transcription/control.rs 停止、排空或取消识别，释放管理器。停止采集可再开始，不等于已保存答案。“结束会话并保留历史”或显式保存调用 interview_session_save → interview_sessions.rs；恢复校验内容摘要，导出经过凭据脱敏。

## 核心取舍与兼容

|取舍|范围及原因|
|---|---|
|直接复用|Tauri 主窗、CPAL/Core Audio、已适配的 cidre、Whisper GGML 引擎、SQLx 会议查询、识别工作线程、录音释放。源码可追踪，不需要另装 Meetily、运行旧后端或逆向二进制。|
|薄层适配|tingxian_audio.rs 读写旧配置、按选中模型启动；session-commands.ts 统一主窗控制；tingxian_runtime.rs 提供离线资源；保留主窗 TranscriptProvider 的本机崩溃恢复写入。不要在拆窗重复挂载。|
|听弦实现|中文启动/音频/历史与错误恢复；同屏浏览无需替换现场；旧记录无可靠角色时不填造对方、本人与 AI 回答。展示窗只读。|
|退役|旧工作台入口、上游侧栏、录音后处理、示例笔记、全局拖放、模型下载/更新提示及分析 provider 从运行树退出。已从公开源码移出无调用的旧侧栏、布局内容组件、后处理组件、详情组件及 6 个占位资源；macOS 安装包资源目录已移除单独分发的旧摘要模板。Windows 资源覆盖和仍被旧模块编译时引用的内置模板另计。移出前通过 TypeScript 模块解析核对 894 条导入、515 个源文件及 51 个导出文本，10 项均无引用。|

macOS 两个标识保持原状：公开版 io.github.jinchunliu.meetilyinterview，自用版 local.meetily.interview。各自 Application Support/<标识>/ 下：recording_preferences.json 保存设备与录音偏好；meeting_minutes.sqlite 保存 transcript_settings、旧 meetings/transcripts 及听弦 interview_sessions（包含问答与使用量）；interview/profile.sqlite 管资料和事实；models/ 管权重。崩溃恢复还使用原 WebView 来源下的 MeetilyRecoveryDB；界面改名不改数据库名或 origin。本次不跨应用标识搬运私人数据，也不扫描钥匙串：听弦回答密钥沿用进程内配置，旧 transcript_settings 的凭据列与音频设置分开，不由本次改动清除。TCC 由 macOS 按应用身份/签名判定，沿用标识不能保证更新后绝不重询。

优先打开已有 .sqlite；若只有原目录的 meeting_minutes.db，以 SQLite 一致快照保留已提交 WAL，临时库迁移及校验通过再发布；失败保留源文件并可重试。已有库打开失败不删除 WAL/SHM。旧数据库不会自动变成带角色的 AI 问答。已存快照可恢复并导出；旧会议/旧恢复记录可原样读取及导出。

联网边界：离线 Whisper、设备枚举、历史和本机检索不需要网络。用户点击额外 Whisper 模型下载时访问配置中 Hugging Face 的 whisper.cpp 仓库；包内 small 不需要下载。回答、视觉、背景整理、连接测试使用用户启用的模型端点，沿用各自的发送确认与资料授权。保留的上游 API、更新器或 PostHog 实现本身不是请求证据。公开包不包含个人资料或 API Key。

## 0.6.3

macOS 现在向 Metal 查询当前进程可以使用的默认设备。设备不可用时，Whisper 使用 CPU 并关闭 Flash Attention。对上表曾触发崩溃的同一条 6.92 秒合成问句，用本次发布配置构建的 Rust 库验证了两个分支。受限进程的 Whisper 日志显示使用 BLAS，正常 Mac 用户会话显示使用 Metal，两次均返回完整终稿。0.6.3 的安装包包含此修复。

0.6.2 虽能保存具名输出，创建 Core Audio tap 时却没有传递这个名字。0.6.3 从已有名字偏好解析唯一的已连接输出，将其 UID 写入单声道 tap，设备测试与会话采集共用该选择。默认设置仍创建全局单声道 tap。不存在或重名的输出会提示重新选择。已在 Mac 上核对实际输出的名称与 UID，并在系统的 CATapDescription 上检查手选和默认两种配置。设备字段参考 [Apple 的 Core Audio tap 样例](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)。

公开版与自用版源码已分别核对。自用配置还曾保留上游更新 URL 和可启用的遥测初始化配置，现已与公开版一致地停用。工作台主路径没有挂载原更新或遥测入口。保留的 Rust 插件注册、命令、CSP 白名单与源码里的网址本身不能证明曾经发生网络请求。

**第一批可以独立提交的最小改动：** 公开版提交 2f6b9ab：frontend/src/components/interview/AudioSettings.tsx、两个听弦 page.tsx、frontend/src-tauri/src/tingxian_audio.rs、lib.rs、interview.rs、whisper_engine/{commands,whisper_engine}.rs。用户点工作台“音频设置”时仍留在现场；可选设备与 Whisper，换模型后采集使用实际选中的模型。其余迁移不必与这一批同时生效。
