# 逐条本人修订与当前版本检索

2026-11-07，接续 `294a512` 的 P2 源码实现；安装版和真实用户库未变更。

资料片段可在「已导入资料 → 查看已导入片段 → 修订这条」保存本人声明、完成状态和依据。修改内容会撤销勾选确认，必须再次确认才保存。原文、定位和原索引哈希保持不变；新声明标记 `user_asserted`，不能将练习或岗位内容升级为个人经历证据。可查看单条修订历史，也可从「查看全部修订」读取同一资料库/路径下已更换来源版本的旧记录。

## 数据与生效

- 在原有 SQLite 增加 `record_assertions` 历史表、当前版本视图及可重建的 `assertion_search` FTS 缓存。更新事务同时写版本、索引和资料库版本号；失败整体回滚。
- 当前声明绑定资料库 root、来源 path/hash、片段 ID 和类别。同文件不变的重新导入保留声明；换文件内容、提取字段、类别或资料库不会将旧声明自动套入新来源。旧版保留供显式核对。
- 默认检索只使用最新声明文本参与匹配，不使用被替代的原文关键词。返回结构仍保留原文，并独立附声明。正文提示只发送当前文本及其来源；声明边界提示按实际命中加载，不为每次对话固定追加。
- 来源过期、尚未生效、核对后内容改变或日期无效时，不参与默认检索与背景整理。未知时效保持原有可检索状态，并标明未核对。历史仍可读取。
- 背景整理把手动声明标为 `user_asserted`，引用文本哈希属于声明自身；`original_source` 单独指向原文件/提取版本，不借用源文件哈希为声明背书。
- 带来源事实卡同时保存当时的声明版本；来源声明更新后，旧事实卡需重新核对。没有说出口的旧 AI 草稿会从后续请求上下文中排除，本人实际发言保留。
- 普通修订在会话或模型请求进行中拒绝写入；独立显示窗口不能调用修订接口。原先的即时撤回流程继续取消旧请求并等待退出。
- 清空索引将全部修订和派生 FTS 纳入格式 3 归档，验证可恢复副本后才清空。移动废纸篓失败时不改变数据库。

上下文估算区分原始提取、去重的当前个人声明、修订历史存储、FTS 存储、摘要、一次请求保守上界和输出预留；手动声明加入整库估算。UTF-8 字节只作为保守 token 上界，不是服务商 tokenizer，也不冒充实际 usage。历史和 FTS 的存储字节不当成请求 token。

- 原生 interview 回归 47 项通过，1 项真实废纸篓用例保持忽略；当前测试使用隔离临时数据和模拟窗口。

- Chrome 中使用真实组件、现有主题样式和内存模拟 IPC，验证编辑、状态选择、确认、保存、原文及版本展示。它不是安装版或实际资料库的端到端验收。
- 12 道相同上下文的提示准备：精简风格候选搭配方法卡，输入 UTF-8 字节中位数减少约 14.5%。若再重复追加完整口语卡，反而增加约 0.5%。两种口径各自留档；不把候选语义改写称为完全相同规则的去重。
- 本地规则装配 p95 约 0.61 ms（精简组，12 次初测），不包含 FTS、进程启动、ASR、网络和模型。实际 token、费用、首字时延、自然度、完整回答质量及真人朗读未测试。25% 输入压缩目标尚未达到。

原答题风格继续生效；候选未晋级。四角色评审只在离线编排层，实时不会启动四角色齐评。Harness² 默认关闭，新增付费调用为 0，冻结的 35 文字题与 12 截图题未改。

综合背景/岗位摘要缺少细粒度依赖图，因此有任一本人修订、撤回或不适用于当前的来源时，保守停用这些派生摘要和旧 AI 草稿。即便重新整理摘要，也不会自动解除这项保护；当前片段检索继续工作。语义岗位视图、故事卡、细粒度依赖和完整多源更新矩阵仍需后续实施。v1/v2 导入和旧事实/会话格式兼容；新的手动声明不会由旧格式导入隐式创建。
