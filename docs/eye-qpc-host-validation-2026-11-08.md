# AV-E5b Rust 原生 QPC 接收

基线 `e5d52d9f52fecdf5ab06c2f6cae17d470d37b9d7`，独立眼部分支。
接续[原生 worker 协议](eye-qpc-stream-validation-2026-11-08.md)。本轮没有修改 NVIDIA
实现或启用 SDK；把已经存在的显式协议接入宿主监督器和有界校正结果接收器。

## 假设和实现

假设：固定 worker 的原始 QPC 和校正像素能够通过 Rust 接收器进入共同时间线，
身份/版本/时间错误及停止竞态不会产生有效输出。决策价值是建立共同输出控制器
后续可用的输入边界。停止条件为时间重标、跨版本降级、原画面回退或停止后交接；
失败保留并定位，不能把成功入队当成外部设备或会议验收。

- `begin_qpc_stream_if_current` 返回独立 `QpcStreamFeed`，输入为 `QpcStreamFrame`。
  不接受旧毫秒 Frame；没有旧 preview、MF 激活 endpoint 或任意进程路径的 UI 入口。
  固定 worker 仍由原 Job、父进程监视、停止信号和有界输入写线程拥有。
- 启动参数选择 input v2，Ready 必须同时匹配 header v2 / endpoint v3，最终报告
  必须是 protocol 4；旧路径仍要求 input/Ready v1、endpoint v1、report 3。
- `NativeCorrections` 和旧预览复用受限管道连接与取消后 I/O 退役机制，检查真实
  server PID/session、capability、完整 Ack，拒绝错误代次/重复帧/未知版本/长度/
  保留位/旧时间字段。读一个载荷最多 500 ms，只保留一个当前结果。
- 校正结果的 capture 和 completion 独立且有序，completion 不早于 capture、
  不晚于当前 QPC。输入新鲜度、完整载荷读完和最终交接分别检查原采集 250 ms 租约。
  不以接收时刻续期；协议失败清空旧结果并关闭输入租约。
- 宿主保存最多 64 条已准入的 `(id, capture_qpc)`，只占元数据。结果必须对应原输入，
  不能自行改时间；已从有界记录淘汰的旧 ID 计 unverifiable 并丢弃，不猜测或补时间。
  输入仍为一个最新待写帧加一个在写帧；停止清空记录和待写像素。
- `with_current` 是受同一停止锁保护的短原生交接，None 表示没有有效校正画面。
  不允许在回调内再次调用 Controller/Feed/reader、等待/写设备或延后重播。

构建和证据在 D 盘。没有真实摄像头/麦克风、播放、SDK 推理、设备注册或安装升级。

## 接下来必须完成的边界

当前 Timeline 交接验证是**输入入队**，未将新 reader 自动绑定到 `JointOutput`。
Timeline 与真实端点有独立生命周期；reader 停止不能自动证明另一个已准备端点停止。
接线必须让 worker/receiver 故障及时共同撤销视频和原声，保护已排期窗口与代次，并在
独立接收线程和输出所有者间使用有界交接。不能在音频输出线程执行最多 500 ms 的
管道读，也不能在停止锁内执行设备等待/写入来掩盖竞态。

仍未完成：共同 owner 绑定、真实摄像头时间映射/本人原声采集、NVIDIA 实际效果、
外部排空恢复、虚拟音频设备、主窗交互、更新安装版、会议接收端 P95 ≤100 ms 和
长期稳定性/商业分发许可。旧实时辅助、教育与冻结数字人分支保留，没有稳定版发布。
