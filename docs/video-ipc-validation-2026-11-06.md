# Windows 视频跨进程传输验收

最终测试提交 `7abcfcf25c352cf6ee7fc17e49fe48ef0ff4a862`；主体实现 `b6b7529d146708b1b9056fee2efe0268d047ea85`。分支 `feat/windows-eye-local-20261106`。本轮只改原生视频组件、测试与文档，前端、助手核心、资料格式、基础安装包和 Mac 0.6.5 UI 基准未改变。

## 实际实现

`FramePublisher` 和媒体源内的 `PipeReceiver` 通过本机命名管道传递已处理 NV12 帧。受保护 DACL 只允许生产者登录会话与 LocalService；后者不获创建同名管道实例权限。握手核对随机连接凭据、实际生产者 PID/会话及客户端身份，拒绝远程路径与远程客户端。连接信息不进入日志或用户偏好。

媒体源可从显式传入的 MF 激活属性建立通道，并从对外的源属性中移除临时凭据。默认仍为中性画面。旧代次帧丢弃；异常退出、断线、空闲读超时或格式错误使当前代次失效。停止会取消并等待本组件的重叠 I/O 完成后释放句柄，不自动重新连接。载荷长度在分配/读取前核对，帧存储与发送均有界。实现与边界详见[协议](../video/windows/IPC.md)。

当前已连通两个普通用户进程和真实 COM/MF 样本输出。实际 FrameServer/LocalService、主应用控制、GPU worker、组件安装和会议接收尚未验收。命名管道的复制开销尚未做性能测量；不能用协议通过替代有效帧率或端到端延迟。

## 验证决定与结果

假设：真实双进程链路可保留像素、拒绝错误连接身份和旧代次，并在停止/故障后中性化。决策价值是判断能否进入 FrameServer 安装和眼部 worker 接入。错误/旧像素、越权接受、临时凭据泄露、取消阻塞、进程残留或无界分配均阻止推进；不减少断言。

本轮未遇到编译或产品检查失败。异常清理缺口来自代码复核，新增预期失败场景用于证明失败后也能释放准确的子进程句柄，没有因此终止未知进程。

新增十组检查：

1. 子进程启动中途失败后准确回收，不残留进程。
2. 两个独立进程通过身份检查，全部 NV12 可见像素一致；核对实际管道 DACL。
3. 远程停止、新代次及迟到旧帧隔离。
4. 生产者跳过析构直接退出，输出端观察 EOF 并切中性画面。
5. 显式断开取消正在等待的读取，本测试断言耗时小于 500 ms。
6. 错误 PID、会话和连接凭据分别拒绝，输出仍中性。
7. 非本机管道路径在建立连接前拒绝。
8. 超大载荷声明在分配/读取前拒绝，返回明确协议错误。
9. 故障后显式新连接恢复；用户停止同时关闭传输。
10. MF 激活属性接通传输，公开源属性不含临时凭据。

取消检查只覆盖该合成场景；未测停止时延分布、真实摄像头释放或对端画面停止。两普通用户进程和 DACL 检查不证明 LocalService 的实际权限兼容，更不是对同用户恶意进程或管理员的安全沙箱。
