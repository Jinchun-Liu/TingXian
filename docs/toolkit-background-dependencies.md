# 背景来源依赖

2026-11-07，接续 `9327204` 的 P2 实施。新整理背景按实际使用的来源版本生效：相关资料修订、过期、撤回或更换提取内容后，背景、岗位与未应用的设置建议停止使用。无关资料变化不再使新背景整体失效。没有依赖清单的旧背景仍按保守规则处理。

上一批代码的岗位读取只检查了撤回，没有覆盖本人修订及过期；本批已补齐。这份记录修正早先文档对该分支的描述。

## 保存与重新生效

- 原有 SQLite 的 `background_library` 保存 `profile_dependencies`，包含资料库、路径、索引内容哈希、类别、共享状态、审核时效和本人修订版本。它是程序观察到的依赖，不是模型生成的引文或真实性证明。没有新增独立事实库。
- 整理器记录实际送入综合步骤的既有来源标识；标识在调用模型前去除，用量计量请求也不携带它。原生端只接受本次读到的版本。导入来源与背景依赖在同一事务发布。
- 当前文件替换旧提取时，旧提取不参与普通综合。本人修订与原文分开；即使原始文件不变，提取字段改变也不能自动把旧声明绑定到新片段。
- 资料变化后，界面显示“背景待更新”。仅编辑摘要措辞不能刷新依赖；重新整理并核对应用才可使用新版本。旧背景和逐条历史仍可查看。
- 外部 Agent 的 v1/v2 导入格式不变，应用依据实际导入记录建立依赖。外部包不能声明已吸收桌面的本人修订，也不能伪造内部依赖标识。本文不把导入包的自报哈希当成已核实原文件的证明。
- 撤回来源时先取消背景任务，再等待其操作锁与旧网络请求退出后确认，防止背景整理占锁期间继续发送后续批次。原文件不删除，采集会话不因撤回而结束。
